# terp の設計方針

terp は、ターミナルを複数開いて素早く切り替えるための macOS 用アプリである。2026-10-23 から、Orca に代わる並列のエージェント開発の道具を目指す（ブランチ `feature/orca-replacement`）。

## 目的

次の 3 つを柱とする。

1. ターミナルの切り替えが速い。
2. テーマなどを設定で変えられる（拡張性）。
3. 新しいターミナルを手軽に開ける。

前提として、表示と操作を通常のターミナルにできるだけ近づける。`claude`・`codex` などの CLI が通常のターミナルと同じように動くことを必須とする。

## 構成

| 層 | 採用 | 理由 |
| --- | --- | --- |
| アプリ | Electron | VS Code・Orca と同じ構成で、`claude`・`codex` との互換性の実績が多い |
| 端末の描画 | xterm.js（WebGL 描画） | VS Code の端末と同じ部品。テーマを JSON と CSS で変えられる |
| 疑似端末 | node-pty | 同上。N-API の配布物があり、Electron 用の再ビルドが不要 |

採らなかった案と理由:

- Tauri: macOS の WKWebView で xterm.js の描画に癖があり、端末の入出力の中継を Rust で書く必要がある。
- Swift + SwiftTerm: テーマや拡張を足すたびに Swift の実装が要り、拡張性の柱に合わない。
- libghostty の組み込み: 組み込み用の API が安定していない。

メモリの使用量は Ghostty より多くなる。これは受け入れる。

## 通常のターミナルに近づけるための決めごと

- シェルはログインシェル（`$SHELL -l`）で起動する。Finder から起動したアプリは PATH を引き継がないため。
- 環境変数: `TERM=xterm-256color`、`COLORTERM=truecolor`、`TERM_PROGRAM=terp`。`LANG` が UTF-8 でなければ `ja_JP.UTF-8` にする。
- 起動元の環境変数（`ELECTRON_*`・`npm_*`・`CLAUDECODE`・`CLAUDE_CODE_*`・`NODE_OPTIONS`）はシェルへ渡さない。npm・npx から起動したときに npm が足す `EDITOR=vi` も渡さない。渡すと zsh が vi の打ち方で始まり、行の編集のキーが効かなくなる。
- 文字幅は Unicode 11 の規則に従う（Unicode11 アドオン）。
- キー: ⌘ の付くキーはアプリが受け取り、それ以外はすべてシェルへ送る。Option は Meta として扱う。Shift+Enter は ESC + CR を送る（`claude` の改行。VS Code の `/terminal-setup` と同じ）。行の編集のキーは iTerm2 の「自然な文字編集」・Terminal.app に合わせる: ⌥←→ は単語の移動（`ESC b`・`ESC f`。xterm.js の既定の `ESC[1;3D` は zsh・bash・claude が単語の移動として受け取らない）、⌘←→ は行の頭と末尾（`^A`・`^E`）、⌘⌫ は行の頭まで消す（`^U`）。⌃←→ は xterm.js の既定（`ESC[1;5D`）のまま（macOS が Space の切り替えに使うことが多い）。
- URL とパスのリンクは、⌘クリックか右クリックで開く（2026-10-27 利用者の指示。以前は普通のクリックで開き、文字を選ぼうとして開いてしまっていた）。URL は既定のブラウザ、ファイルはタブ、フォルダは Finder で開く。右クリックは xterm.js がリンクに知らせないため、指を置いているリンクを覚えておき、端末の `contextmenu` で開いて既定の動きを止める。リンクの外の右クリックは止めない。指を置いている間は「⌘クリックか右クリックで開く」を説明に出す。自己診断は `TERP_SELFTEST_PATHLINKS=1`。
- アプリのキーは VS Code と macOS の端末アプリに揃える（2026-10-26 利用者の指示）。
  - `⌘F` は表示中の枠の右上に検索欄を出す。`Enter`・`⌘G` で次、`⇧Enter` で前、`Esc` で閉じて端末に戻る（`@xterm/addon-search`。当たりの色は xterm.js の決まりで `#RRGGBB` に限る）。`⇧⌘G` は先に「変更の一覧」が使っているため、前の当たりには割り当てない。ファイルのタブでは Monaco の検索を使う。
  - `⌘=`・`⌘-`・`⌘0` は端末の文字を1ptずつ変え・戻す。設定の大きさからの差（`fontDelta`）を `tabs.json` に残し、6〜40pt に収める。
  - `⇧⌘T` は閉じたタブを新しい順に最大20件まで開き直す。端末は同じ場所・名前で新しいシェルを開く（中で動いていたものは戻らない）。作業（worktree）を消して閉じた端末と、シェルの `exit` で終わった端末は覚えない。
  - 左の一覧は VS Code と同じ `⌘B` とし、`⌘D` は空けておく（Ghostty・iTerm2 の「右に分割」）。
  - 自己診断は `TERP_SELFTEST_SHORTCUTS=1`。

## 切り替え（柱 1）

- 開いたターミナルはすべて生かしたまま、表示だけを差し替える。
- Chromium の WebGL は同時に 16 個前後しか持てないため、WebGL 描画は表示中のターミナルにだけ付け、裏に回したら外す。
- 操作: 左の一覧、`⌘1`〜`⌘9`、`⌃Tab`（直前のターミナル）、`⌘⇧[`・`⌘⇧]`（一覧の前後）、`⌘W`（閉じる）。`⌘P`（名前と作業場所のあいまい検索）は未実装。
- 一覧の各行に、名前、動いているプログラム名と作業場所、状態の印を出す。
- 名前の優先順: ダブルクリックで付けた名前 > claude などが端末のタイトルに出した題名 > 作業場所のフォルダ名。作業の下のシェルとホーム（`~`）のシェルは「ターミナル」と出す（2026-10-28 利用者の指示。`~` だけでは何の行か分かりにくかった）。行の名前の前には、エージェントならそのアイコン、シェルならターミナルのアイコン（`>_`）を出す。
  - claude は会話の題名を自分で作り、タイトル（OSC 0/2）に出す（2026-10-23 実測。例 `◐ Python フィボナッチ数列の生成`）。先頭の記号は、回転（◐◑ など）が作業中、`✳` が入力待ちを表す。
  - 題名は、前面のプログラムがシェル以外のときだけ名前に使う。`Claude Code` などの既定のタイトルは使わない。
  - 記号が回転から `✳` に変わったとき、そのターミナルを見ていなければ「終わった」の印（緑）を付ける。
  - codex のタイトルの出し方は未確認。
- シェルの状態の印: 出力中（緑）・裏で出力があった（青）・通知あり（黄）。通知は OSC 9 / 777 とベルで受け取る。
- 作業場所と動いているプログラム名は、本体が 1.5 秒ごとに `lsof` を1回呼んでまとめて拾う。
- ⌘ の付くキーはアプリのメニューで受ける。`⌃Tab` は端末が先に受け取るため、画面側で処理する。
- 左の一覧は `⌘B`（VS Code と同じ。メニューの「表示 → 左の一覧」）か一覧の上端のボタンで隠せる（2026-10-26 利用者の指示）。隠している間は、上の帯の左端（信号機ボタンの右）に出すボタンを置く。隠した状態は `tabs.json` の `sidebarHidden` に残し、開き直しても保つ。localStorage は自己診断の窓と保存先を共有するため使わない。自己診断は `TERP_SELFTEST_SIDEBAR=1`。

### 全体の一覧

- 「移動 → 全体の一覧」（`⌘M`）と、ワークスペース切り替えの下の「一覧 ⌘M」で、窓いっぱいに全ワークスペースのターミナルを並べる。表示中のワークスペースを先頭にし、所属ごとに「開いているタブ」（画面上部のタブの帯に出ている端末。表示中のワークスペースだけ）・リポジトリ（左の一覧の並び順）・「その他のターミナル」の順にまとめる。開いているタブの端末はリポジトリのまとまりから外して先頭に出し、リポジトリが多くても作業中の端末まで送らずに済むようにする（2026-10-26 利用者の指示）。リポジトリ名の見出しは `--text-md` の太字・本文の色とし、ワークスペース名は一段大きい `--text-lg` にして上下の関係を保つ。もう一度 `⌘M`、`Esc`、閉じるボタン、または背景を押すと閉じる。
- タイルの上に既存と同じ状態の印・見出しを出す（お気に入りの星は 2026-10-27 にドラフトへ置き換えて外した）。見出しは要件（claude などのエージェントが付ける端末の題名 `agentTitle`）とし、2行を超えたら末尾を省く。要件が無ければ `displayName` の名前にする。見出しの下に、自分で付けた名前（要件を見出しにしたときだけ）・ブランチ（作業の外なら場所）・プログラム名を薄い色で1行に並べる。リポジトリ名だけでは端末を見分けにくいという指摘による（2026-10-26 利用者の指示）。要件は利用者が書かず、エージェントが話の中身に合わせて題名を付け替えるたびに変わる。題名を付けないエージェント（codex など）とシェルでは、要件は出ない。下には xterm の表示範囲の末尾8行を、テーマの端末の前景色・背景色で出す。裏の端末には WebGL が付かないため、キャンバスの写しは使わない。表示中の端末は強調色の外枠、許可待ちと終わった端末は印の色の細い枠で示す。選択は強調色の線と見出しの面で示す。
- 上端に「すべて」「開いているタブ」、リポジトリ（左の一覧の並び順）、「その他のターミナル」のタブを並べ、絞り込み後の件数を添える（2026-10-26 利用者の指示）。押したタブのまとまりだけを出し、`⌃Tab`・`⌃⇧Tab` で順に切り替える。リポジトリとその他のタブでは、開いているタブの端末も元のまとまりに入れて出す。選んだタブは、窓を開いている間は次に一覧を開いたときも保つ。タブが多ければ横に送る。
- 開いている間だけ500msごとに中身と印を更新する。検索欄とタイルの選択を保ち、閉じたら更新を止める。開閉には動きを付けない。
- 開いたときは操作中の端末を選び、検索欄に焦点を置く。要件・名前・リポジトリ名・ブランチ名・作業場所を、大文字小文字を区別しない部分一致で絞り込む。端末が無ければ「ターミナルはない」、一致しなければ「合うターミナルはない」を出す。
- 矢印キーは描画されたタイルの位置から移動先を選ぶ。左右は同じ行、上下は隣の行の横位置が最も近い端末へ移り、端では止まる。`Enter` またはクリックで既存の `activate` を呼び、所属が違えばワークスペースを切り替えてから移る。
- `TERP_SELFTEST_OVERVIEW=1` は一時フォルダの `TERP_CONFIG_DIR` と組み合わせ、2所属・3端末以上で開閉・まとまり・出力・絞り込み・所属をまたぐ移動・裏の許可待ちを確かめる。偽の claude に端末の題名を付けさせ、要件が見出しに出ることも確かめる。`node src/overview.test.js` は窓を開かず、絞り込み・見出しと下の行の組み立て・矢印キーの移動先の計算を検査する。

## ワークスペースとドラフト

2026-10-26 追加。仕事と個人などのリポジトリ・ターミナルをワークスペースに分け、左の一覧ごと切り替える。常駐プロセスと xterm の要素は残し、表示する一覧・タブ・枠だけを差し替える。

- `projects.json` は `workspaces: [{ id, name }]`・`activeWorkspace` と、各リポジトリの `workspace`・`draft` を持つ。旧形式は読み込み時に `default`（名前「既定」）を補い、全リポジトリを所属させる。次の保存時に新形式で記録する。並べ替えは表示中のリポジトリだけに作用し、他のワークスペースの位置と属性を保つ。5秒ごとの読み直しと、ドラッグ中の更新停止は維持する。
- 左の一覧の上端に名前付きの切り替えボタンを置く。開いたメニューから選択・作成・名前の変更・削除を行う。名前は既存と同じ `<dialog>` と入力欄で編集する。削除は最後の1つ、またはリポジトリかターミナルがある場合に無効とし、理由を併記する。本体でも常駐プロセスの一覧を照合し、削除を拒否する。
- 「ワークスペース」メニューの `⌃⌘1`〜`⌃⌘9` は登録順の指定、`⌃⌘]`・`⌃⌘[` は次・前への巡回とする。上のタブと `⌘1`〜`⌘9`・前後の移動は、表示中のワークスペースの同じ作業だけを対象にする。`⌃Tab` の履歴もワークスペース内に限る。
- ターミナルは作成時のワークスペースを `setMeta` で預ける。既存の端末に所属が無ければ、cwd を含む最も深いリポジトリ・worktree の所属を使い、該当しなければ表示中の所属を使う。所属先のリポジトリ・作業に cwd が入らなければ、そのワークスペースの「その他のターミナル」に出す。cwd の変化では所属を変えない。
- リポジトリの見出しと端末行の右クリックメニューに「ワークスペースへ移す」を置く。リポジトリと端末の所属は独立する。リポジトリに属する開いたファイルはリポジトリとともに移す。リポジトリの追加・新しい作業・新しい端末は表示中のワークスペースに入れる。既に登録したリポジトリを追加した場合は、重複せず表示中の所属へ移す。
- `tabs.json` の `workspaces` に、所属ごとの最後のタブ・枠の木・操作中の枠・最後の端末・タブ履歴を残す。ファイルの所属は `fileWorkspaces` に残す。旧形式の控えは「既定」の配置として読む。初めて開く所属では最初の端末を表示し、端末が無ければ新規作成の空表示にする。常駐プロセスが消えた後は、`sessions.json` の旧 ID と新 ID を対応させ、配置の端末キーも戻す。
- 各ワークスペース名の横には、許可待ち ＞ 終わった ＞ 考え中の印と同状態の件数を出す。閉じた切り替えボタンには全ワークスペースで最も急ぐ状態を出し、裏の知らせを残す。印は既存の `.work__status` と共通とする。「次の要対応」はワークスペース順・リポジトリ順・作業順・端末順で全所属を巡り、必要なら切り替える。Dock は引き続き全所属を合計する。
- 星はドラフトの出し入れに使う（下の「ドラフト」と「すべて」）。リポジトリは `projects.json`、端末は常駐プロセスのメタ情報と `sessions.json` に残す。
- 「すべて」のドラフト済みのリポジトリは強調色を背景に使い、不透明度は `--surface-sidebar` と同じ `config.window.opacity` から作る。文字色は `favcolor.js` の純粋関数で WCAG のコントラスト比を計算する。4.5未満なら RGB の各成分を同率で下げ、4.5以上になる最初の色を使う。黒でも届かない暗い強調色は、指定どおり黒を採用する。テーマ・強調色・透過の変更時に `applyConfig` で再計算する。星と操作ボタンにも同色を使う。エージェントの状態の印は既存の色・動きを保つ。
- その他のターミナルの作業場所の直下に、端末を開いた後で `.git` ができたら（`git init` した時点）、窓の右下に「foo が git の管理を始めました」と出し、端末を foo にまとめるか尋ねる（2026-10-27 利用者の指示。ルートで claude を立ち上げて新しいプロジェクトを作り、push する使い方）。
  - 「foo にまとめる」でリポジトリを端末と同じワークスペースに登録し、端末の `workPath` に foo を入れる。`workOf` は `workPath` を作業場所より優先するため、端末は foo のまとまりに移り、変更の一覧・ファイル・新しい端末の場所も foo になる。端末は閉じないため claude の会話は続く。claude 自身の作業フォルダは元のままである。claude の会話の記録は立ち上げたフォルダごとに分かれるため、foo で立ち上げ直す方式は採らない。
  - 勝手には登録しない。「今はしない」を押したものは、この窓の間は聞き直さない。どの端末が作ったかは分からないため、できる前から開いていた同じ場所の端末のうち、エージェントで最後に触ったものに尋ねる。
  - 設定の「通知」の「新しいリポジトリの案内を試しに出す」で、`~/sample-app` を見つけたことにした案内を出せる。試しの案内は「まとめる」を押しても何も登録しない。本物の案内を表示中なら出さず、設定の画面に理由を出す。
  - 見るのは直下（1段下）だけで、隠しフォルダと `.git` がファイルのもの（worktree）は除く。5秒ごとに、その他のターミナルの作業場所ごとに1回だけ見る。`workPath` は常駐のプロセスの名前と控え（`sessions.json`）に残し、開き直しても保つ。自己診断は `TERP_SELFTEST_NEWREPO=1`、単体テストは `node src/newrepos.test.js`。
- アイコンだけのボタン（`.icon-btn`・エージェントのボタン）は、カーソルを1秒重ねると説明をチップで出す（`src/renderer/tooltip.js`。2026-10-29 利用者の指示）。OS の title の吹き出しは時間と見た目を選べないため、重ねている間だけ title を外し、離すと戻す。押す・キー・スクロールで消す。自己診断は `TERP_SELFTEST_SIDEBAR=1` の後半。
- リポジトリのカードは縦の余白を詰める（同日の利用者の指示）。見出し 24px、作業の行 26px、ターミナルの行は最小 40px、カードの間は 6px。
- リポジトリを追加するボタンは、「すべて｜ドラフト」の切り替えの右に置く（2026-10-29 利用者の指示。以前は上端の、一覧を隠すボタン・設定のボタンと並べていた）。
- Finder のフォルダを左の一覧に落とすと、リポジトリとして足す（2026-10-27 利用者の指示。受けるのは左の一覧の中だけで、端末の枠へのドロップはこれまで通りパスの入力）。載せている間は強調色の枠と「フォルダを離すとリポジトリを追加」を真ん中に出す（下端のボタンに重ねると字が入れ替わったように見えるため）。印は Finder からのドラッグ（`Files`）だけに出し、タブなど terp の中のドラッグには出さない。リポジトリの中のフォルダを落とすと、git が返すリポジトリの一番上を足す。git でないフォルダとファイルは足さず、理由をワークスペース切り替えの下に出す。自己診断は `TERP_SELFTEST_DROPREPO=1`。
- 左の一覧の幅は右端をドラッグして 200〜520px で変えられる（2026-10-27 利用者の指示。リポジトリ名がほとんど見切れていた）。つかむ所を選んで ←→ で 16px ずつ、ダブルクリックで既定の 248px に戻す。幅は `tabs.json` の `sidebarWidth` に残す。あわせて、リポジトリの見出しの載せたときだけ出すボタン（ドラフトの星・外す）は、隠れている間は場所も取らないようにした（以前は見えないまま3つ分の幅を取っていた）。240px より狭いと上端の「作業」の題を消す（題があると上端のボタンが窓の外へはみ出した）。「新しい作業」の ＋ は常に出す。自己診断は `TERP_SELFTEST_SIDEBAR=1`。

## エージェントの状態

前面のプログラムがシェル以外の端末には、許可待ち・考え中・終わった・待機の順で状態を付ける（2026-10-24 追加）。`src/renderer/app.js` の純粋関数 `agentState`・`reduceAgentStatus`・`permissionMessage`・`agentStatusText` が、判定・遷移・許可の文字・経過の表示を受け持つ。

| 状態 | 根拠と下ろす条件 | 印と2行目 |
| --- | --- | --- |
| 考え中 | 作業中の題名、または直近2秒以内の出力。打鍵後500ms以内の出力は除く。考え中に戻ったら許可待ちと終わったを下ろす | 強調色の回る輪。印に指を置くと「考え中 1:23」（1時間以降は「1時間2分」） |
| 許可待ち | OSC 9 / 777 の本文が `permission / approv / allow / 許可 / 承認` に一致する。打鍵または考え中への復帰で下ろす。表示だけでは下ろさない | テーマの黄色の塗りと「!」 |
| 終わった | 作業中から入力待ちへの題名の変化、または許可を求めない OSC 通知。許可待ち中には付けない。表示中で窓に焦点があれば付けず、表示または考え中への復帰で下ろす | テーマの緑の塗り。印に指を置くと「終わった · 3分前」 |
| 待機 | 上記のどれでもない | 中抜きの丸 |

状態は印だけで示し、文字は一覧に出さない（2026-10-24 変更）。考え中の開始時刻と応答の完了時刻を端末ごとに持ち、500msごとの再描画で印の説明（title）の経過を更新する。動きを減らす設定では輪を回さず、透明度だけを変える。流し直し中は許可待ち・終わった・通知の印を付けない。

左の一覧とタブには同じ印と読み上げ名を出す。従来の `data-state` は互換性のため残し、4状態は `data-agent-state` に出す。シェルの出力中・未読・通知・待機の判定は維持する。全端末の状態を通知の設定へ連動させる案は採らない。利用者が通知を切っていても、画面と Dock では状態を確認するためである。

作業行の右端には、許可待ち・終わった・考え中の順で最優先の印を1つ出す。同じ状態の端末が複数あれば、その状態の件数を添える。作業の子要素の表示によらず作業行に残し、押すと一覧順で先頭の該当端末を表示する。「移動 → 次の要対応」（`⌘⇧J`）は、許可待ちがあれば許可待ちだけを、無ければ終わった端末を全ワークスペースの一覧順で巡回する。

窓は許可待ちと終わったの合計を `dock:badge` IPC で本体へ送り、本体が `app.dock.setBadge` で表示する。0件なら消す。通知の節にある `dockBadge`（既定 `true`）は通知センターの有効・無効から独立する。本体でも現在の設定と送信元・整数の件数を検査する。

`TERP_SELFTEST_AGENTSTATUS=1` は一時フォルダの `TERP_CONFIG_DIR` と組み合わせる。名前が `claude` の偽 CLI を起動し、本体が名前を拾うまで待つ。題名・OSC・打鍵から一覧・タブ・作業行・Dock・メニュー・シェルの表示を検査する。本体の最後の Dock 表示値は `main.__test.dockBadge` から読む。Electron の窓を使う自己診断は今回未実施である。

- 左の一覧などアプリの枠の色は、テーマの背景色と文字色を混ぜて作る。テーマを変えるだけで枠も揃う。
- 枠の文字色は、地の色とのコントラスト比が4.5以上になる色を、テーマの文字色・テーマの背景色・黒・白の順に選ぶ。アプリの背景色をテーマと別に決めても、文字が地に溶けない（2026-10-29 利用者の指摘）。

- JSON の誤りと、見つからないテーマ名は、一覧の下に警告として出し、直すまで消さない。読めない間は既定の値で動く。
- 透過のため、ウィンドウは常に `transparent: true` で作る（作成時にしか指定できない）。背景は一覧と端末の面にだけ塗り、xterm.js 側の背景は透明にする。両方に塗ると、透過のときに重なって濃くなる。
- xterm.css は `.xterm-viewport` を `#000` で塗るため、透明に上書きしている。
- ぼかしは Electron の vibrancy を使わない。vibrancy は窓の裏にすりガラスの板を敷く仕組みで、暗いテーマでは板がほぼ不透明に見え、透過が効かなくなった（2026-10-23 に利用者の目で確認）。Ghostty と同じく macOS の非公開の関数 `CGSSetWindowBackgroundBlurRadius` を koffi で呼ぶ（`src/blur.js`）。macOS の更新で関数が消えたら、ぼかしだけが無くなり透過は残る。
- 透かす（不透明度が1未満）かぼかすときは、窓の影を切る（`setHasShadow(false)`。Ghostty と同じ）。透明な窓の影は四角い窓の形のまま描かれ、丸い角の外に四角い線と隅の影が残っていた（2026-10-27 利用者の指摘。画面の収録の許可が無く、自己診断では見た目を撮れないため、影の有無だけを `TERP_SELFTEST_THEME=1` で確かめる）。不透明なら影を戻し、ほかの窓との境目を保つ。
- macOS の全画面は窓を専用の Space へ移し、後ろに壁紙も他の窓も無くなるため、透過しても灰色の板しか見えない（Ghostty はこのため全画面の間は透過を切る）。terp は全画面に入ったら、いまの壁紙を窓の後ろに敷き、窓と同じ半径でぼかす（`src/wallpaper.js`）。壁紙の場所は JXA で `NSWorkspace.desktopImageURLForScreen` に聞く（System Events を通さないため、操作の許可を求められない）。HEIC は画面で出せないため `sips` で長い辺 2560 の JPEG にし、設定のフォルダの `cache/` に控える。全画面の Space には元々他の窓が無いため、見た目はほぼ透過と同じになる。Space を作らない全画面（`setSimpleFullScreen`）も試したが、利用者は新しい Space に入ることを望んだため採らなかった（2026-10-24）。
- 端末の面は枠の側で塗るため、xterm.js にはテーマの背景色の透明度だけを 0 にした色を渡す（`rgba(テーマの背景, 0)`）。最小のコントラストは xterm.js がこの色を基準に計算する。以前は黒の透明を渡しており、明るいテーマで濃い文字が黒地に合わせて薄められ、薄い文字（`\e[2m`）には黒い四角が付いていた（2026-10-28 利用者の指摘）。自己診断は `TERP_SELFTEST_THEME=1`。
- 端末の描画（WebGL）は `blendFunc(SRC_ALPHA, ONE_MINUS_SRC_ALPHA)` で重ねるため、透明な面では画素の透明度が a×a になり、薄い文字や文字の縁が後ろの色で白く抜けた。`WebGL2RenderingContext.prototype.blendFunc` を包み、透明度だけ `ONE, ONE_MINUS_SRC_ALPHA` で足し合わせる（2026-10-28 利用者の指摘。明るいテーマで読みにくかった）。自己診断は `TERP_SELFTEST_THEME=1` が画素の色を測る。
- 余白・最小のコントラスト・カーソルの形と点滅は、既存の設定ファイルに無ければ既定値を使う。値に誤りがあれば警告を出し、その項目だけ既定値で動く。
- キー割り当ての設定とプラグインは未実装。

### Ghostty の設定の取り込み

設定画面の「外観」の先頭に「Ghostty から取り込む」を置く。読み取りは本体の IPC、書式の解析と写し方は `src/ghostty.js` が受け持つ。入出力と環境は呼び出し側から渡す。

[Ghostty の公式資料](https://ghostty.org/docs/config)に従い、次の順ですべての存在するファイルを読む。後に読んだ値を優先する（2026-10-24 確認）。

1. `$XDG_CONFIG_HOME/ghostty/config.ghostty`
2. `$XDG_CONFIG_HOME/ghostty/config`
3. `~/Library/Application Support/com.mitchellh.ghostty/config.ghostty`
4. `~/Library/Application Support/com.mitchellh.ghostty/config`

`XDG_CONFIG_HOME` が未設定なら `~/.config` を使う。`TERP_GHOSTTY_CONFIG` を指定した場合は、その1ファイルを入口にする。`config-file` は記述元の末尾で順に読み、相対パスは記述元のフォルダを基準にする。`~/` はホームフォルダへ展開する。同じ実体のファイルは1回だけ読み、輪と重複を止める。先頭に `?` があるパスの欠落は無視し、必須ファイルの欠落や読み取りの失敗は表示して保存を止める。

空行と `#` で始まる行を除き、最初の `=` で項目と値を分ける。値の前後の空白と外側の二重引用符を除く。同じ項目は最後の値を使い、`font-family` だけは順に連結する。空の `font-family` はそれまでの並びを消す。

| Ghostty | terp | 写し方 |
| --- | --- | --- |
| `theme` | `theme` | `light:A,dark:B` は `B`。`listThemes` に無ければ写さない |
| `font-family` | `fontFamily` | 名前を二重引用符で囲み順に連結し、`Menlo, "Hiragino Sans", monospace` を末尾に足す |
| `font-size` | `fontSize` | 数値にし、9〜32 に収める |
| `background-opacity` | `backgroundOpacity` | 0.2〜1 に収める |
| `background-blur`・`background-blur-radius` | `backgroundBlur` | 真偽か数値。数値は既存のぼかしと同じ0〜100に収め、別名同士でも後の値を優先する |
| `window-padding-x`・`window-padding-y` | `paddingX`・`paddingY` | 1値か2値。2値は平均を四捨五入し、0〜40に収める |
| `minimum-contrast` | `minimumContrast` | 1〜21 に収める |
| `foreground`・`background` | `foreground`・`background` | `#` の有無を問わず6桁の16進だけ。色の名前（`white` など）は写さない |
| `palette` | `palette` | 行ごとに読み、0〜15 の番号の分だけ写す。同じ番号は後の行を使う |
| `cursor-style` | `cursorStyle` | `block`・`bar`・`underline`。`block_hollow` は `block` に置き換え、理由も表示する |
| `cursor-style-blink` | `cursorBlink` | `true`・`false` を写す |

テーマが無ければ「テーマが見つからない」、`macos-option-as-alt` は「terp は常に Meta」として写さない。`bold-color`・`faint-opacity`・`window-padding-balance`・`keybind` など、表に無い項目は「terp に無い」と表示する。数値や真偽の形式を読めない項目も、理由を付けて写さない。`config-file` は読み取りの指示として処理する。

確認欄は変わる項目のラベルと前後の値、写さない項目と理由、読んだファイルのパスを表示する。同じ値は差分から除き、差分が無ければ「変わる項目はない」として取り込めない。「やめる」は保存せず、「取り込む」は差分をまとめて `updateConfig` で保存し、設定欄を描き直す。設定が見つからない場合は入口を無効にして理由を表示する。

取り込みは1回きりとし、以後は terp の設定を正とする。Ghostty の設定を監視すると、terp の画面で直した値が上書きされるため、継続的な同期は行わない。保存後は既存の terp の設定監視を通して、開いている端末へ反映する。

`TERP_SELFTEST_GHOSTTY=1` は一時フォルダの `TERP_CONFIG_DIR` を必須とする。偽の Ghostty 設定とテーマを作り、追加ファイル・差分・理由・取り消し・保存・端末と余白への反映・再取り込み・入口の欠落を確かめる。`TERP_GHOSTTY_CONFIG` は試験中だけ一時ファイルへ向ける。

## エージェントを並べて動かすときの手助け

claude を何枚も並べて動かしたときに、許可に答えるために画面を離れる・どれが何をしているか開くまで分からない、という手間を減らす。

- 今なにしてる：claude と codex の会話の記録の末尾から、最後の道具の呼び出しを短く言い換える（「実行 テストを流す」「編集 app.js」など）。考え中・許可待ちのあいだ、左の行の2行目と ⌘M のタイルの下の行に出す。考え中・許可待ちのものは4秒ごとに読み直し、それ以外は状態が変わった直後に1回だけ読む。記録が見つからないものは30秒ごとに探し直す。
- 同じファイルの重なり：同じ記録から編集したファイルと時刻を拾い、30分以内に2枚以上が同じファイル（絶対パスが同じもの）を書き換えていたら、両方の行に「同じファイル」の印を付ける。worktree を分けていればパスが違うため印は付かない。
- 許可待ちのカード：表示していないエージェントが許可待ちになり、画面の一番下に「Do you want …?」と番号付きの選択肢（❯ が今の選び）があれば、右下にカードを出す。押す直前に画面を読み直し、同じ画面のときだけ矢印と Enter を送る（番号のキーは版で扱いが違うため使わない）。「No, and tell Claude …」を選んだときは続けて文を打つため、そのターミナルへ移る。カードのボタンはターミナルの入力を奪わない。設定の「通知 → 許可待ちに右下のカードで答える」で切れる。
- タブのはみ出し：幅に入らないタブ（6割以上隠れているもの）を「他 N」にまとめ、押すと一覧から選べる。隠れた中に許可待ち・終わった・考え中があれば、いちばん急ぐものの印を付ける。
- ⌘M の並び：まとまりの中を、許可待ち、終わった、考え中、それ以外の順にする。並びは開いたときの状態で決め、開いている間はタイルを動かさない。

## AI の手伝い

なくても困らないが、あれば手間が減る所で claude を呼ぶ（2026-10-28 利用者の指示）。設定の「AI の手伝い」で全体と機能ごとに切れる。

| 機能 | 既定 | 呼ぶとき | 渡すもの |
|---|---|---|---|
| コミットメッセージを書く（`aiCommitMessage`） | 入 | 「変更」の面の「AI で書く」を押したとき | ステージした差分（最大 12,000 字）・概要・直近8件の件名 |
| ターミナルに名前を付ける（`aiNameTerminal`） | 入 | 行の右クリックの「AI で名前を付ける」 | 画面の末尾（最大40行・2,000 字）・場所・動いているプログラム |
| 無地のターミナルの題名を自動で予測する（`aiAutoTitle`） | 切 | 1分ごとに見回り、画面が変わって5秒落ち着いた無地のターミナルを1枚だけ。同じターミナルは10分あける | 同上 |

- トークンを抑えるため、`claude -p` を `--system-prompt`（独自の短い指示）・`--disable-slash-commands`・`--strict-mcp-config`・`--setting-sources ''`・`--no-session-persistence`・`--tools ''` で呼ぶ。CLAUDE.md・スキル・MCP・フックを読まず、1回の読み込みが約 7,100 から約 600 トークンになった（実測）。`--bare` は API キーでしか認証しないため使わない。
- モデルは `aiModel`（`haiku` が既定、`sonnet` も選べる）。1日の回数の上限は `aiDailyLimit`（既定 30、0 で上限なし）。使った回数とトークンは `~/.config/terp/ai-usage.json` に日ごとに残し、設定の画面に「今日の使用量」として出す。
- 自動の題名は画面の文字を送るため既定で切る。断られたら（上限・切ってある）30分休む。手で付けた名前があるターミナルには付けない。題名は `aiTitle` として常駐のプロセスに預ける。
- 自己診断は `TERP_SELFTEST_AIASSIST=1`（偽の claude を `TERP_CLAUDE_BIN` で差し替える）。

## 設定の画面

`⌘,` で窓いっぱいに開く（2026-10-23 利用者の指示）。左にメニュー、右に選んだ項目の設定を出す。Esc か × で閉じる。設定ファイルを直接開くのは、メニューの「設定ファイルを開く」に移した。

- 雛形: `src/renderer/settings.js` の `SECTIONS` に、メニューの項目と設定の項目（種類・設定ファイルの名前・説明）を書くと画面が組み上がる。種類は theme・select・text・number・range・toggle・color・action（`FIELD_TYPES`）。設定の名前は `config.js` の `DEFAULT_CONFIG` と同じにする（知らない名前は書き込みで拒否する）。
- 保存は変えたらすぐ行い、保存のボタンは置かない（文字の欄は入力が止まって 800ms 後と、欄から離れたとき）。書いた後は設定ファイルの監視を通して画面に反映する。
- 書き込みは `config.json` を読んで、変えた値だけを差し替えて書く。画面に無い値や手で書いた値は残す。`null` は「書かない（既定に戻す）」として消す。JSON が壊れているときは書かずに、直すよう知らせる。
- 範囲の外の数は書かずに知らせる。一覧に無い値（手で書いたテーマの名前など）も、消さずに「見つかりません」と付けて出す。
- 項目は、外観、AI エージェント、通知、詳しい設定の順に並べる。外観ではテーマ・強調色・フォント・文字の大きさ・背景の不透明度・ぼかし・Dock のアイコンの色を扱う。AI エージェントでは確認なしで起動・メインの指定・登録一覧を扱う。
- 通知では通知の有無・応答の終わり・ベル・表示中の端末・音・返答の文を切り替える。通知を切ると従属する5項目を操作できない。Dock の件数は独立して切り替える。試用ボタンは通知を切っていても使え、現在の音の設定で通知する。
- テーマは名前で絞り込む一覧にし、使用中の印を付けて最初にその位置を表示する。マウスを載せる操作と上下矢印はプレビューだけを変え、クリックと Enter で保存する。選択前に色を比べられないプルダウンは使わない。
- プレビューはターミナルの出力・選択とカーソル・16色・左の一覧・強調色のボタンを表示する。`config.getThemeColors` が実際の適用と同じ色変換を使い、IPC で画面へ返す。強調色の指定があれば優先し、無ければカーソルの色を使う。画面は名前と強調色ごとに結果を再利用し、プレビューの要素だけに色を指定する。幅が足りなければ一覧とプレビューを縦に並べる。
- 見出しの「AI で好みを作成」で、明るさ・好きな色や雰囲気・くっきり具合・色の温度・鮮やかさ・強調色・見やすさ・土台を質問する。温度と鮮やかさは「ふつう」を既定とする。強調色は指定するときだけ色の欄を操作できる。見やすさでは赤と緑の見分けやすさと、アプリの背景色も作るかを選ぶ。ダイアログは窓の高さに収め、中をスクロールできる。下部の操作は固定する。
- 土台は「新しく作る」が既定で、「今のテーマを土台にする」も選べる。本体が `config.getThemeColors(rawConfig().theme)` で上書き後の色を読み、土台の色として渡す。名前が `null` なら内蔵の色を使う。土台の色は画面から受け取らない。
- `src/themegen.js` は `aiassist.ask('theme', system, prompt, options)` を使う。設定の `aiModel` に従い、haiku は60秒、sonnet は120秒で打ち切る。独自の短い system 指示を使い、設定・スキル・MCP を読ませない。回答・追い指示・今の案・土台の色は、命令として扱わないデータとして JSON で渡す。新しい API キーは持たない。
- AI は最初に、日本語80字以内の `concept` で景色・主になる色・差し色を決める。その後に背景・文字・差し色、最後に16色を決める。温度は主な色相、鮮やかさは HSL 彩度の目安で伝える。くっきり具合は文字と背景のコントラスト比で伝える。やわらかいは4.5〜6、ふつうは6〜7、くっきりは7以上とする。
- 16色は赤のエラー・緑の成功・黄の警告・青の情報などの役目を保ち、雰囲気の色に寄せる。赤と緑の見分けやすさを選んだら、朱・オレンジと青緑へ寄せ、明るさにも差を付ける。強調色を指定したらカーソルにその色を使う。アプリの背景色を求めたら、端末の背景と同系統で少し暗い色を作る。明るいテーマなら少し濃い色にする。
- CLI の `result` から名前・6つの色・16色の配列を検証する。`concept` は任意で、文字列なら120字まで残す。`appBackground` は求めたときだけ必須とし、`#rrggbb` を検証する。文字と背景は WCAG コントラスト比4.5以上、16色の1〜6・9〜14と背景は3以上を必要とする。不足した番号と理由を添えて1回だけ作り直し、それでも不足すれば失敗として理由と再試行を表示する。
- 成功時はプレビューの上に `concept` を控えめに出し、下に200字以内の「直したいこと」と「この案を直す」を出す。今の案は本体で `validateTheme` を通し、追い指示と合わせて AI に渡す。直した案を次の土台にして、修正を重ねられる。修正に失敗したら案と入力を残す。「作り直す」は追い指示を使わず、同じ回答から新しく作る。作成中も閉じられ、閉じた後の結果は破棄する。
- AI が作ったテーマは「適用」のときだけ `themes/<名前>` に Ghostty の書式で保存する。同名は ` 2`・` 3` を付け、別名のファイルへ書いてから置き換える。`concept`・`appBackground` はテーマのファイルに書かない。`save('theme', 名前)` が設定を更新する。アプリの背景色を求めた場合だけ `appBackground` と、そのテーマの名前を `appBackgroundTheme` に保存する。強調色を指定し、既存の `accent` があれば `null` に戻してカーソルの色を使う。指定しなかった設定は変えない。
- テーマの作成は明示の操作のため、`aiAssist` や各機能の入切に依らず使える。1日の上限は共有する。修正とコントラスト不足による作り直しも1回ずつ数え、設定の「今日の使用量」に「テーマ」として表示する。
- `TERP_SELFTEST_THEMEAI=1` は一時フォルダの `TERP_CONFIG_DIR` を指定して使う。偽の claude を `TERP_CLAUDE_BIN` で渡し、`-p <文>` と `--system-prompt` を検査する。質問・concept の表示・追い指示の繰り返し・現在の色を土台にする処理・背景色と強調色の保存・16色の不足による再生成も確かめる。単体テストは `src/themegen.test.js` に置く。Electron の画面の自己診断はこの環境では未実施である。

- AI エージェントの登録一覧は、未導入・非表示のものも含めて表示する。行を押すと、表示名・実行ファイルの絶対パス・起動引数・確認を飛ばす引数・環境変数を編集できる。文字の欄は 800ms 後とフォーカスを離したときに保存し、編集内容を残して保存の失敗を表示する。
- 行の「表示する」と上下ボタンは `agents` の非表示設定と配列順を更新する。既知のものは「既定に戻す」で上書きを除去し、追加したものは確認ダイアログの後で削除する。「メインにする」は `mainAgent` を更新する（`src/renderer/settings.js`）。
- 登録一覧の初回表示と「確かめ直す」のときだけ `agents:status` を呼ぶ。結果は設定画面を閉じるまで再利用する。`src/agentstatus.js` は `loginEnv()` の環境と `CONFIG_DIR` で `--version`、Claude の `auth status`、Codex の `login status` を実行し、それぞれ 5 秒で打ち切る。エージェントに設定した環境変数は、状態確認には付けない。
- 版は出力の最初の行だけを表示する。ログインは済み・未・確かめられない・確かめる方法が無いのいずれかと、認証方式の語だけを返す。認証の生出力や実行失敗時の出力は IPC へ渡さない。
- `TERP_SELFTEST_AGENTREG=1` は一時フォルダの `TERP_CONFIG_DIR` と組み合わせる。偽の CLI を作り、状態・表示切り替え・引数・環境変数・パス上書き・追加削除・並び替え・メインの指定・アイコン・再確認を検査する。`TERP_AGENT_STATUS_FAKE` は状態確認に使う実行ファイルを指定フォルダで差し替え、見つからなくても本物へ戻さない。Electron の画面を使う検査は今回未実施。

| `notifySound` | `true` | macOS の既定の通知音を使う |
| `notifyMessage` | `true` | 応答の終わりの本文にエージェントの返答を使う |

`app.js` は最新の設定と枠の木から通知の可否を判断する。窓に焦点が無ければ表示中でも知らせる。同じ端末では、前の通知から3秒未満の出来事をまとめる。一覧の通知の印は既存の条件を保ち、OS 通知の有無には連動させない。

題には「セッションの表示名 · 作業の名前」を使う。作業の名前はリポジトリ名とブランチ、作業の外ではフォルダのパスとする。OSC 9 の `4;` で始まる進捗と、通知以外の OSC 777 は扱わない。

`notifyMessage` が有効な `done` は、本体の `src/agentreply.js` で返答を探す。Claude はシェルの pid を `snapshot.claudeSessions` で会話の ID に結び付け、`~/.claude/projects` と `~/.claude2/projects` から記録を探す。結び付けは15秒間使い回し、控えの保存で得た ID も利用する。最後の利用者発言（`tool_result` だけの行を除く）より後の assistant の `text` を順につなぎ、`isSidechain` の行を除く。

Codex はシェルの子孫で名前が `codex` のプロセスを `/bin/ps` で探す。`/usr/sbin/lsof` で開いている `rollout-*.jsonl` を求め、最後の `task_complete.last_agent_message` を使う。探索の ps と lsof は2秒で打ち切る。既存の `claudeSessions` は内部で10秒待つため、専用の子プロセスで呼び、CLI と ps を含むプロセス群を2秒以内で打ち切る。

出来事から最大2秒間、250ms 間隔で読み直す。前回その端末で通知に使った返答との違いは、本文を保持せず SHA-256 で判定する。探索を含む全体に2秒の期限を設ける。記録は末尾256KBだけを読み、利用者発言や完了の行が無ければ末尾1MBまで広げる。読めないファイルと壊れた行は飛ばす。

返答の本文は純粋関数 `formatReply` で整える。コードの囲みは「（コード）」に置き換え、見出し・強調・リンク・箇条書きの飾りを外す。表は区切り行を除き、セルを空白でつなぐ。改行と連続空白をまとめ、制御文字を除く。Unicode の符号位置で300字を超えたら300字と `…` にし、作業の名前を後ろに付けない。返答はログに出さない。

返答が無い場合、他のエージェント、設定が無効な場合、ベル通知では従来の本文を使う。OSC 9 の文字か OSC 777 の `notify;題;本文` の本文を使い、空なら「応答が終わった」か「ベルが鳴った」とする。後ろに作業の名前を付け、制御文字を除いて全体を200字までにする。設定画面には「返答の文を出す」と、ロック画面や画面の共有で返答の中身が見えることがある旨を表示する。

`notify:show` は `{ id, kind, title, body }` を受け、`done` の場合だけ返答を探してから `src/notify.js` の Electron `Notification` で出す。IPC の返答は既存の `safe` による `{ ok, value, error }` の形にする。待機中に端末が終了した場合や、通知設定が切れた場合は出さない。通知非対応なら何もしない。音の有無は本体でも現在の設定を読み、`silent` に反映する。

本体は端末ごとの通知の参照を保持し、同じ端末の新しい通知・押下・閉鎖・端末の終了時に解放する。押下時は `notify:activate` で ID を送り、窓が `activateKey(termKey(id))` で作業ごとのタブ表示も切り替える。窓の `Notification` API は使わず、本体で参照と窓の復帰を管理する。

macOS の「システム設定 → 通知」で terp の通知を許可する必要がある。通知が未許可の場合も試用ボタンから動作を確かめられる。

`TERP_SELFTEST_NOTIFY=1` は一時フォルダの `TERP_CONFIG_DIR` と組み合わせる。`TERP_SELFTEST` 中は実通知を出さず、本体の `notify.__test.shown` に内容を積む。返答の探索は `TERP_REPLY_FAKE_DIR/projects/<任意のフォルダ>/<会話ID>.jsonl` と、同じ偽フォルダ内の Codex 記録だけを使う。`agentreply.__test.setLookup(fn)` で会話 ID と Codex のファイルを差し替える。差し替えが無い場合も実記録と実プロセスの探索には戻らない。

`notify.__test.click(index)` で押下を再現し、窓は `showInactive` で表示して焦点を奪わない。端末への `printf` で題名・ベル・OSC を発生させ、設定・抑止・本文・移動・一覧の印を検査する。偽の記録で Claude と Codex の抽出、1秒後の追記、2秒での代替本文、300字への省略も検査する。今回、Electron の画面を使う自己診断は未実施である。

## 作業（worktree）

Orca の中心の機能に倣い、課題ごとに git の worktree を作り、その中でエージェントを動かす。利用者が Orca で使っていて terp に求めた機能は、作業ごとの worktree・変更の差分の確認・ファイルの編集・PR の作成の4つ（2026-10-23 聞き取り）。最初に作業ごとの worktree を作った。

- 左の一覧は「リポジトリ > 作業 > ターミナル」の3段にする。表示中のワークスペースのどの作業にも入らないターミナルは「その他のターミナル」に出す。
- terp は、一覧に出すリポジトリ・ワークスペース・お気に入りを記録する（`~/.config/terp/projects.json`）。worktree の一覧・ブランチ・変更の数は、毎回 git から読む（5 秒ごとと、ウィンドウに戻ったとき）。Orca やコマンドで作った worktree もそのまま出る。
- ターミナルの作業への振り分けは、そのワークスペース内で作業場所（cwd）を含む worktree のうち、いちばん深いもので決める。所属を記録しないため、`cd` で別の作業へ移れば一覧の場所も移る。
- 新しい作業は `<リポジトリ>.worktrees/<ブランチ名の / を - にしたもの>` に作る。手元の worktree の置き方はリポジトリごとにばらばらだった（横並び・`.worktrees/`・`-worktrees/`）ため、新しく作るものだけ揃える。
- 同じ名前のブランチが既にあれば、それを使う。無ければ「元にするブランチ」（既定は `origin/HEAD` の先、無ければ本体の今のブランチ）から作る。作ったら、選んだコマンド（`claude`・`codex`・なし）をターミナルで起動する。
- 作業の削除は `git worktree remove` だけで行い、`--force` は付けない。変更のあるファイルが残っている作業は、削除のボタンを押せなくし、理由を出す。ブランチは消さない。消す前に、その作業のターミナルを閉じる。
- 「一覧から外す」は `projects.json` から消すだけで、ファイルには触れない。
- リポジトリの並びは `projects.json` の順で、見出しの行をドラッグ＆ドロップするか、見出しを選んで ⌥↑ / ⌥↓ で変える（2026-10-23 利用者の指示）。つかんでいる間と記録を書いている間は、5 秒ごとの読み直しを止める（読み直すと古い順に戻って見えるため）。

### 作業画面の分割

2026-10-24 追加。上の帯の下を最大6枠に分け、ターミナル・ファイル・サブエージェントの記録を同時に表示する。

- `panes.js` の木は、葉を `{ type: 'pane', id, key }`、分割を `{ type: 'split', dir, children, sizes }` とする。`dir` は左右が `row`、上下が `column`。`sizes` の合計は1とする。操作関数は DOM に依存しない。
- 操作中の枠は1つとし、`activeKey` はその枠のタブを表す。タブの中身は既存の要素を枠へ移し、未表示の要素は帯の下の木の外にある置き場で隠す。要素を作り直す方式は、シェル・編集内容・スクロール位置を失うため採用しない。
- タブを押すと、表示済みならその枠へ移り、未表示なら操作中の枠を入れ替える。分割中だけ操作中の枠を強調色の線で囲む。枠の右上の × は枠だけを閉じる。
- 各枠の上端には、分割していないときも高さの低い題名の帯を常に出す。端末には一覧と同じ状態の印・`displayName` の名前と、薄い色の「プログラム名 · リポジトリ / ブランチ」を並べる。作業に入っていなければ作業場所を短く表記する。名前は字数で切らず、帯の幅に収まらないときだけ末尾を省略する。帯の `title` に名前・プログラム名・作業場所のフルパスを出す。
- 端末の帯のダブルクリックは、一覧と共通の名前入力を開く。`Enter` で確定、`Esc` で取り消し、空欄で自動の名前に戻す。ファイルは名前と作業のルートからの相対パス・未保存の印、サブエージェントの記録はタブの名前を出し、帯からは改名しない。
- 帯の文字は `--text-sm` とし、端末と同じ奥の背景を透かす。1枠では下の境界線だけを出し、分割中の操作中の帯は境界線も既存の強調色に揃える。× は帯の右端に収める。本文を帯の下に置き、FitAddon と ResizeObserver で残りの領域を測り直す。名前・状態・未保存の印は500msごとに更新し、編集中の入力欄は保つ。
- 上のタブ、左の端末と押せるサブエージェントの行、右のファイルの行を `text/x-terp-tab` でドラッグする。リポジトリの並べ替えの `text/x-terp-project` と区別する。未表示のファイルと記録はドロップ時に開く。
- 枠の端25%は、その側へ半分ずつ分割する。角では近い端を選ぶ。中央へのドロップと6枠でのドロップは中身を入れ替える。同じタブは重複させず、移動元の枠は畳む。
- 表示中のタブを自分の枠の端へ落としたら、そのタブを新しい枠へ出し、元の枠には同じ作業で1つ前に見ていた未表示のタブを出す。1つ前が無ければ同じ場所で新しいターミナルを開く。以前は何も起きず、別のタブへ移ってからでないと分割できなかった（2026-10-26 利用者の指摘）。
- 境目は約5pxとし、ポインタを捕まえて隣り合う割合を変える。各枠の最小寸法は120pxとし、入れ子の分割の最小寸法も合算する。窓が狭ければ作業画面内でスクロールする。ダブルクリックで隣り合う割合を半分ずつに戻す。
- 表示中の端末すべてに WebGL を付け、未表示の端末から外す。サイズ変更は FitAddon と既存の ResizeObserver で反映し、Monaco は既存の自動レイアウトを使う。
- タブを閉じた枠は、同じ作業の最近見た未表示タブで埋める。無ければ枠を畳み、最後の枠なら「新しいターミナル」の空表示に戻す。
- `⌘\` は同じ場所に新しい端末を開いて右へ分割する。`⌘⌥` と矢印キーは、画面上でその方向に隣接する枠へ移る。
- 枠は固定できる（VS Code のグループのロック。2026-10-26 利用者の指示）。題名の帯の錠のボタン（固定していない枠ではマウスを載せたときだけ出す）か「移動 → 今の枠を固定」で切り替える。固定した枠は、タブを選んでも中身を差し替えず、固定していない枠のうち並びの先のものに出す。全部固定なら右に枠を足し、6枠ならそのまま今の枠に出す。ドラッグで落としたとき・その枠のタブを閉じたときは、利用者がその枠を指しているため差し替える。固定は葉の `locked: true` として `layout` に残す。自己診断は `TERP_SELFTEST_LOCK=1`。
- `tabs.json` の `workspaces` の所属別の `layout` に枠のキーと割合を残す。最上位の `layout` にも表示中の配置を残す。復元時は消えたタブ・重複したタブ・サブエージェントの記録を除き、1つの子だけ残った分割を畳む。古い控えに `layout` が無ければ1枠で開く。
- 枠内の操作とドロップ予告は作業画面内の層に閉じ込め、差分表示（`z-index: 2`）・メニュー（10）・設定（20）の下に置く。

自己診断は `TERP_SELFTEST_PANETITLE=1` で長い題名・状態・改名・分割・ファイルの帯・端末の収まりを、`TERP_SELFTEST_SPLIT=1` で操作・ドラッグ・サイズ変更・メニューを、`TERP_SELFTEST_PERSIST=1` → `2` → `3` で枠とタブの復元を確かめる。

- 窓の地（左の一覧・端末の面・右の面・設定と一覧の画面の地）のほかは角を丸くする（2026-10-28 利用者の指示）。端末の枠は窓の端から `--space-2` 離した角の丸いカードにし、分割した枠の間は線ではなく隙間にする（つかんでいる間だけ真ん中に強調色の線）。操作中の枠は縁の色を強調色にする。上のタブ・差分の面・画像のプレビュー・⌘M の履歴の列も角を丸くする。
- ⌘M の一覧を閉じた後は、戻したフォーカスを一度外して付け直す。閉じた直後に戻したフォーカスでは、macOS の日本語入力が端末に付かず英字だけになることがあった（2026-10-28 利用者の指摘。フォーカスを移し直すと戻った）。窓が裏にあると requestAnimationFrame が回らないため setTimeout で戻す。

## ファイルの閲覧と編集

### ドロップによるパスの入力

2026-10-24 追加。Finder のファイル・フォルダと、右のファイル一覧からの `⌥` 付きドロップで、表示中の枠にパスを入力する。

- `document` の `dragover`・`drop` で `Files` の既定の動作を止め、枠の外でもファイルへの画面遷移を防ぐ。内部のタブ移動とリポジトリの並べ替えは従来の種類で扱う。
- 実パスは preload の `webUtils.getPathForFile(file)` から取得する。廃止された `File.path` は使わない。実パスの無い項目は除く。
- ターミナルには空白・タブ・シェルの記号をバックスラッシュで逃がしたパスを入れる。複数は空白で区切り、最後に空白を1つ付ける。Enter は送らない。
- 入力には xterm の `term.paste(text)` を使い、括弧付き貼り付けを反映する。生の文字列を直接 PTY へ書く方式は、claude などで入力が分かれるため採用しない。落とした枠を操作中にして入力の焦点を移す。
- 文字のエディタには素のパスを改行で区切り、Monaco が求めたドロップ位置に挿入する。位置を求められなければカーソル位置を使う。挿入は1回の取り消しで戻せる。
- 画像などの閲覧枠とサブエージェントの記録には入力しない。パスのドラッグ中は分割の予告を出さず、受け取れる枠に強調色の細い線を出す。
- 右のファイルとフォルダの行には `text/x-terp-path` を付ける。`⌥` があればパスを入力する。ファイルの行は従来の `text/x-terp-tab` も持ち、`⌥` が無ければ分割・入れ替えを行う。
- パスのエスケープと入力先の判定は `droppaths.js` に置く。Monaco 独自のドロップ処理より前に受け取り、ファイルを別途開かせない。

自己診断は `TERP_SELFTEST_DROPPATHS=1` で実行する。合成した `File` には実パスが無いため、`window.__terp.dropPaths(paneId, paths)` で入力を確かめる。既定の動作の抑止と内部ドラッグは合成イベントでも確かめる。

### 閲覧と編集の動作

- 端末に出た実在するファイルのパスはクリックでタブに開き、行・桁の指定があればエディタの中央にその行を表示してカーソルを置く。フォルダは Finder で表示する。
- パスのリンクは折り返しをつないで検出する。相対パスは端末の作業場所、次に worktree の一番上から探し、実在確認の結果は5秒間再利用する。
- 右の面の「ファイル」は、表示中のタブの場所を含む worktree の一番上（git の外ならその場所）から木の形で出す。`.git` と `.DS_Store` は出さない。フォルダの中身は開いたときに読み、開いているフォルダだけを 5 秒ごとに読み直す。
- ファイルを押すとタブで開く。文字のファイルは Monaco Editor で編集し、言語は登録された拡張子とファイル名から決める。該当しなければ `plaintext` にする。背景は透明とし、文字・選択・行番号・構文の色とフォントは端末の設定に合わせ、設定の変更時にも反映する。
- Markdown（`.md`・`.markdown` など）は、見出しの「プレビュー」か `⇧⌘V` で整えた見た目に切り替える（2026-10-28 利用者の指示）。もう一度押すと「編集」に戻る。エディタは残したまま出し分けるため、未保存の変更も消えず、プレビューは保存前の内容で描く。最後に選んだ方を覚え、次に開く Markdown もそれで開く（画面の `localStorage`）。
  - `marked`（GFM）で HTML にし、`DOMPurify` でスクリプト・`on*` 属性・フォームの部品を取り除く。どちらも Monaco が既に使う版を直接の依存に足した。チェックの項目は表示だけにする。
  - 相対パスの画像は Markdown の場所から解決する。CSP は変えないため、`http(s)` の画像は出ない。見出しには GitHub と同じ形の id を付ける。リンクは、`#` なら見出しへ、`http(s)`・`mailto` は既定のブラウザ、それ以外のパスは terp のタブで開く。
  - 自己診断は `TERP_SELFTEST_MDPREVIEW=1`。
- Monaco の AMD loader を `app.js` より先に読み、エディタ本体の読み込みは Promise を共有する。作業用ファイルは本体で `min/vs/assets/editor.worker-*.js` を探し、同期 IPC で渡す。CSP は変更しない。
- 2 MB を超える文字のファイルと、先頭 8 KB に NUL を含むファイル（バイナリ）は中身を出さず、既定のアプリで開くボタンを出す。画像は画像として出し、10 MB を超える画像は中身を出さない。
- `⌘S` とメニューの「保存」で表示中のファイルを UTF-8 で保存する。別名に書いてから置き換え、既存のアクセス権を保つ。未保存の変更があるタブは名前の後ろに `●` を付ける。読み込み時・保存時の `mtime` と一致しなければ書き込まず、上書きの確認後に保存する。
- 開いている文字のファイルの `mtime` を2秒ごとに確かめる。未保存の変更が無ければ、カーソルとスクロールの位置をできるだけ保って読み直す。変更があれば「外で変更されました」の帯で、読み直すか、このまま編集するかを選ぶ。「このまま」を選んでも保存時の上書き確認は残る。削除されたファイルは帯で知らせ、タブを残す。
- 「再読み込み」やファイルのタブを閉じる操作では、未保存の変更があれば既存と同じ `<dialog>` の部品で確認する。閉じる場合は保存・破棄・キャンセルを選び、保存に失敗した場合は閉じない。
- 窓を閉じる操作と `⌘Q` は、本体で一度止めて画面に問い合わせる。画面はすぐ応答し、未保存のファイルがあれば全件保存・破棄・キャンセルを選ぶ。2秒以内に画面が応答しなければ閉じる。応答後は利用者の選択を待ち、既存のシェル保持と終了時の控えの保存を続ける。
- 開いたファイルの絶対パス・ターミナルを含むタブの並び・表示中のタブを、設定のフォルダの `tabs.json` に保存する。タブの追加・削除・切り替えから 250 ms 後にまとめて、別名に書いてから置き換える。
- terp を開き直すと、ターミナルの復元後に存在するファイルだけを読み直し、タブの並びと表示中のタブを戻す。文字のファイルは復元後もエディタで開く。右の面の「ファイル」が閉じていても復元する。存在しないタブのキーは捨て、控えに無いタブは後ろに置く。表示していたタブが無ければ、最後に見たターミナルのままにする。復元途中は控えを上書きしない。

## AI エージェントの起動

手元に入っている AI エージェントの CLI を自動で探し、起動のボタンを「新しいターミナル」の上に並べる（2026-10-23 利用者の指示）。

- ログインシェルの PATH から探す（`src/agents.js`）。ターミナルで打って動くものと揃えるため。探すのは `KNOWN_AGENTS` の45種と、設定ファイルの `agents` に書いたもの。
- 登録の一覧と既定の引数は、利用者が Orca 本体の一覧と `agentDefaultArgs` を2026-10-26に読み取ったものを出どころとする。既存12種の後ろに33種を追加した。CodeRabbit は Orca に無く、terp で追加した。
- `command` が PATH に無ければ、定義の `aliases` を順に探す。例えば CodeRabbit は `coderabbit`、`cr` の順に探す。検出結果の `alias` は使った別名（通常の名前なら `null`）を持ち、起動の1行にもその名前を使う。設定で `path` を指定した場合は別名を探さない。
- `agents` の各項目は `{ command, label, args, bypassArgs, path, env, hidden }`。同じ `command` の既定には書いた値だけを重ね、未知のコマンドは追加する。設定の配列順を優先し、未指定の既定はその後ろに並べる。`path` があれば PATH を探さず、絶対パスで存在と実行権限を確かめる。検出結果には導入の有無・場所・既定値・アイコンも含む（`src/agents.js`）。
- `args` も既定値を持てる。Rovo Dev は `acli` に `rovodev run` を付け、確認なしではさらに `--yolo` を付ける。設定ファイルの `args` があれば、空文字も含めて利用者の値を優先する。
- 設定の登録一覧は、件数付きの「連携中」「未連携」に分ける。「連携中」は初め開き、「未連携」は初め畳む。見出しを押して開閉し、状態は設定画面を閉じるまで保持する。各区画では設定の配列順、続いて既定の順を保つ。「確かめ直す」で検出結果が変わると行を対応する区画へ移す（`src/renderer/settings.js`）。
- 左下のエージェントのボタンはアイコンだけを1列に並べ、名前は載せたときの説明（チップ）に出す。確認を飛ばすかなどの説明と「確認なし」の印は出さない（同日の利用者の指示）（2026-10-29 利用者の指示。名前付きの2列は場所を取りすぎた）。
- 未導入か `hidden: true` のものは、左下のボタン・プルダウン・メイン・新しい作業の選択肢に出さない。設定の監視から `applyConfig` と `refreshAgents` を通して起動用の一覧を更新する。
- `env` の名前は `[A-Za-z_][A-Za-z0-9_]*` のみを使う。起動の 1 行を `env 名前='値' … '実行ファイル' 引数` とし、値と実行ファイルの単一引用符を逃がす。環境変数は起動時だけ付ける（`src/renderer/app.js` の `agentCommandLine`）。
- アイコンは `src/renderer/icons/agents/` のローカル SVG を使う。色付きは画像、`currentColor` のものは CSS mask で文字色に合わせる。既知の定義に表示方式を持ち、アイコンの無いものは既存のロボットを表示する。CSP は変更しない。
- ボタンを押すと、表示中のターミナルと同じ作業場所で新しいターミナルを開き、そのコマンドを打つ。空白を含む絶対パスは引用符で囲む。
- 「新しい作業」の画面の「作ったら起動する」も、見つかったエージェントと「起動しない」から選ぶ。
- エージェントを入れたり消したりしたら、ウィンドウに戻ったときに探し直す。
- タブの並びのすぐ右に、＋（新しいタブのプルダウン）とメインのエージェントのボタンを置く（2026-10-23 利用者の指示）。プルダウンには「ターミナル」と見つかったエージェント全部を出す。メインは設定の `mainAgent`（無ければ見つかった最初のもの）で、押すとプルダウンなしで起動する。どちらも ⌥ で確認あり・なしが逆になる。
- プルダウンの最後に、利用者が決めたコマンドを出す（2026-10-27 利用者の指示）。設定ファイルの `commands`（`{ label, command }` の配列）に残し、設定の「コマンド」で足す・並べ替える・消す。選ぶと、エージェントと同じく表示中のターミナルと同じ作業場所で新しいターミナルを開き、`command` をそのままシェルに打つ（引用はしない。パイプや `&&` も書ける）。一覧の下に空の入力欄（表示名・コマンド）を常に出し、「登録」か Enter で足す（2026-10-27 利用者の指示。行を増やすボタンを先に押す形はやめた）。片方が空なら登録しない。登録済みの行は書き換えるとすぐ保存する。手で書いた誤った項目は読み込みで飛ばす。登録が無くても「コマンドを登録」を出し、設定の画面への入口にする。自己診断は `TERP_SELFTEST_COMMANDS=1`。
- 確認を飛ばす起動（2026-10-23 利用者の提案）: ファイルの読み書きやコマンドの実行の確認を出さずに起動する引数（`bypassArgs`）をエージェントごとに持つ。値は Orca の `agentDefaultArgs` と同じ（claude は `--dangerously-skip-permissions`、codex は `--dangerously-bypass-approvals-and-sandbox` など。2026-10-26に利用者が Orca 本体から読み取った値）。
  - 利用者は「ディレクトリへのアクセスを許可せずに起動する」機能と捉えていたが、実際は逆で、確認を飛ばし、codex はサンドボックスも外す。この点を伝えたうえで、普段は確認なしで起動すると決めた。
  - 設定の `skipApprovals` が true なら、ボタンは確認なしで起動する。⌥ を押しながら押すと逆になる。コードの既定は false（確認あり）にし、利用者の設定ファイルにだけ true を書いた。公開しているリポジトリのため、入れただけで確認なしで動くことを避ける。
  - 確認なしで起動したことは、開き直しても残るよう常駐のプロセスに預ける。左の一覧の行の「確認なし」の印は、2026-10-28 に利用者の指示で外した（行が込み合うため）。

左の一覧では、ターミナルのすぐ下に、そのシェルの下で動くサブエージェントを出す。
利用者は説明・最後の操作・経過時間を確認し、Claude の行から記録をタブで開ける。

`TERP_SELFTEST_SUBAGENTS=1` は出力先に偽の設定フォルダを2つ作り、稼働中1件と終了2件で一覧・開閉・追記・タブ・設定ボタンを確かめる。

## git の管理

右の「変更」の面（上の帯の「変更」のボタン、`⌘⇧G`）で、表示中のターミナルの作業場所を含む worktree の git を扱う（2026-10-23 利用者の指示）。

- できること: ブランチと上流との差（↑↓）の表示、変更のあるファイルの一覧（競合・ステージ済み・未ステージ。追跡外を含む）、差分の表示、ステージとステージの取り消し（1件・すべて）、コミット、プッシュ、プル、フェッチ。
- Fetch・Pull・Push のボタンは、git のコマンドと同じ英語で書く（2026-10-29 利用者の指示）。読み直すボタンはその右に置く。右の面の切り替え（ファイル・変更・履歴）の隣に置くと、git の操作でないものと混ざって見えるため（同日の利用者の指摘）。履歴の読み直すボタンは履歴の面の見出しに置く。ファイルの面は定期的に読み直すため、ボタンを置かない。
- 右の面を開いている間は、上の帯のファイル・変更・履歴のボタンを隠す。面の上の切り替えと同じ働きで冗長なため（2026-10-29 利用者の指摘）。変更の数は面の切り替えの「変更」にも出す。
- 認証は terp で持たない。ターミナルで git を打ったときと同じもの（SSH の鍵・キーチェーン・gh の認証・`includeIf` による名義の切り替え）をそのまま使う（利用者の指示「端末内の認証情報を使う」）。
  - Finder から起動したアプリは PATH が細く、SSH エージェントや gh が見つからないことがある。ログインシェル（`$SHELL -i -l -c 'env -0'`）の環境を一度だけ読み、git に渡す。読めなければ PATH だけ足す。
  - 認証の入力を求められると止まるため、`GIT_TERMINAL_PROMPT=0` にする。入力が要る認証は失敗として面に出す。
- コミットする名義（`user.name`・`user.email`）を面に出す。業務と個人のアカウントを使い分けているため、どちらの名義でコミットするかを確かめられるようにする。
- コミットのボタンは、ステージ済みのファイルが無い・競合がある・メッセージが無いときに押せなくし、理由を出す。フック（pre-commit など）はターミナルと同じく走る。
- プッシュは、追跡先の無いブランチなら `--set-upstream origin HEAD` で作る。プルは `--ff-only` で、履歴が分かれていたら失敗として返す（自動でマージしない）。
- 変更を捨てる操作（`restore`・`reset --hard`・`clean` など）は持たない。取り返しがつかないため、ターミナルで行う。
- 差分は 5,000 行で打ち切る。バイナリのファイルは差分を出さない。

### 履歴の閲覧

2026-10-24 に実装。本体は一時リポジトリで検証済み。Electron の自己診断と実画面での確認は未実施。

右の面の「履歴」（上の帯の時計のボタン、`⌘⇧H`）で、表示中のタブの場所を含む worktree の履歴を表示する。
「ファイル」「変更」「履歴」の開閉と選択は `app.js` の `setPanel` に集め、同時に1つだけ表示する。
既存の右の面の幅と重なり順を使い、枠を狭めた場合も一覧と詳細をそれぞれの領域内でスクロールする。

- `src/history.js` はログインシェルの環境で git を呼び、`history:log`・`history:commit`・`history:diff` の IPC で結果を渡す。失敗は既存の `safe` で返す。
- 一覧は `git log --topo-order` で取得し、`src/renderer/historygraph.js` の純粋関数で親ハッシュから列と線を組む。各列が待つハッシュを保持し、最初の親は同じ列、他の親は既存の列か左端の空き列へつなぐ。同じハッシュを待つ複数の列は、そのコミットで合流する。
- 100件ずつ読み、追加時は読み込み済み全件で列を組み直す。1件22pxの行にSVGの曲線と点を表示し、マージは丸と下向きの山形で示す。最大8列まで描画し、超える部分は右端で切る。幹は画面のアクセント色、他の列は端末のテーマ色を使い、設定の変更にも追従する。
- 件名前の札に現在のブランチ、ローカル・リモートのブランチ、タグ、ブランチに属さないHEADを表示する。同じコミット上の同名のローカル・リモートはまとめる。リモート名はgitから取得し、URLのホストがgithub.comならGitHubの印、それ以外なら雲の印を使う。URL自体は窓へ渡さない。タグは端末のmagentaを使う。
- 件名の先頭の種類を太字にし、本文がある場合は「↩」、上流との差に含まれる場合は右端の「↑」で示す。作者と日時は行のtitleに保持する。全ブランチ表示ではHEADの祖先を1回の`git rev-list HEAD`で取得し、祖先ではない行の文字を薄くする。
- 絞り込みは入力終了から300ミリ秒後に行う。16進の4〜40字はコミットを直接指定し、それ以外は件名と作者を OR で検索する。`--grep` と `--author` の集合を合わせ、件名の一致を確認してトポロジー順に返す。絞り込み中は見えているコミット間だけで線を組む。
- ファイルの見出しの「履歴」で、そのパスを変更したコミットだけを表示する。見出しの「×」で解除する。名前変更の追跡（`--follow`）は行わない。
- 面を開いている間は10秒ごとに読み直し、読み込み済み件数と表示位置を保つ。worktree が変わったら先頭から読み、ファイルの絞り込みを解除する。読み込み中の結果は要求の番号で区別し、古い結果で新しい条件を上書きしない。
- コミットの詳細は `c:<worktree>@<ハッシュ>` のタブで開く。同じコミットは再利用し、親のコミットへ移動できる。既存の枠へのドラッグと分割に対応するが、開き直し用の控えには含めない。
- 詳細は全文メッセージ、作者・コミッター、日時、親、印、変更ファイルを表示する。マージは最初の親との差、最初のコミットは空のツリーとの差を表示する。名前変更は元と先の両方を差分に渡す。
- ファイルの行を押すと差分を開閉する。差分の表は「変更」の `renderDiff` を共用し、同じ5,000行の上限を使う。バイナリと打ち切りは文字で示す。
- ハッシュは git の呼び出し前に検証する。履歴を書き換える操作は持たない。
- `TERP_SELFTEST_HISTORY=1` の自己診断は、一時リポジトリでページ追加と線の連続、行の高さ、SVG・マージ・札・本文の印・太字・祖先以外の文字色に加え、未プッシュ、全ブランチ、検索、詳細と差分、親、ファイルの絞り込み、ハッシュの検証を確かめる。`outDir/history-graph.png`に画面を保存する。

## セッションの保持

terp を閉じても開き直しても、シェルと中のプログラム（claude など）は止めない（2026-10-23 利用者の指示）。`link-app` で入れた terp はコードを直すたびに開き直すため、開き直すたびに会話が切れるのを防ぐ。

- シェルは常駐のプロセス `src/ptyhost.js` が持つ。terp の実行ファイルを `ELECTRON_RUN_AS_NODE=1` で Node として起動し、terp からは切り離す（`detached`）。Orca の `orca-terminal-host` と同じ作り。
- terp とは Unix ソケット（一時フォルダの `terp-<設定のフォルダのハッシュ>.sock`）で、1行1つの JSON をやりとりする。ソケットのパスは 104 バイトまでのため、一時フォルダに短い名前で置く。設定のフォルダごとに分かれるため、自己診断は利用者の常駐のプロセスとつながらない。
- 常駐のプロセスは、各シェルの出力の末尾 2 MB を残す。terp がつなぎ直したら、それを流して画面を作り直す。名前・題名・最後に見た時刻・ワークスペース・ドラフトから外したか・シェルに伝えた大きさも預かる。
- 末尾から押し出した出力の中の画面の切り替え（`ESC[?<番号>h`・`l`。全画面表示・マウス・貼り付けの合図など。同期出力の `?2026` は除く）は、番号ごとに最後の値を覚え、流し直す出力の先頭に付ける（`src/hostmodes.js`。2026-10-29 利用者の指摘）。claude の全画面表示は最初に `?1049h` で切り替え、後は差分だけを送る。長く動かすと切り替えが押し出され、開き直すと普通の画面に差分だけが描かれて、ステータス行が消えたり文字が欠けたりした。先頭に付けると全画面表示で戻り、つなぎ直しの最後の描き直し（全画面表示のときだけ大きさを1桁揺らす）が効く。
  - 常駐のプロセスの版は `ptyhost.js` と `hostmodes.js` の中身から作る。動いている常駐のプロセスは入れ替えないため、この直しはシェルを全部閉じて常駐のプロセスが終わった後に効く。
  - 自己診断は `TERP_SELFTEST_REDRAW=1` の後半。全画面表示に切り替えた偽物に 2 MB を超える差分を流させ、開き直した後に全画面表示で戻ることと、一度しか描いていない行が描き直しで戻ることを確かめる。単体テストは `node --test src/hostmodes.test.js`。
- 流し直しは、出力が描かれたときと同じ大きさで行う（2026-10-27 利用者の指摘。開き直すと claude の入力欄が積み重なって入力が見えなくなる、文字の切れ端が残る）。
  - 原因は3つあった。①端末を窓全体の大きさで作ってから流していた。②流した後に大きさを1桁変えて戻す揺さぶりを入れ、戻す側が古い大きさを80ms後に送るため、枠に合わせた後の大きさを上書きしてシェルと画面の大きさが食い違ったままになった。③左の一覧の幅などの控えを、端末を表示した後に当てていたため、大きさが2回変わった。claude（Ink）は前の画面を「1行ずつ上へ戻って消す」ため、大きさが変わると折り返した行を消し損ねる。
  - シェルに大きさを伝えるたびに、そこまでに受け取った出力の末尾 512 文字と大きさを `sizeLog`（最大30件）として常駐のプロセスに預ける。流し直すときは、その末尾が現れた位置で同じ順に画面の大きさを変えながら流す（`src/renderer/replay.js`）。流している間はシェルに大きさを伝えない。表示して枠に合わせたときに、変わっていれば1回だけ伝える。記録の無い前の版の端末は、最後に伝えた大きさでまとめて流す。
  - 幅などの控え（`tabs.json`）は端末をつなぎ直す前に当て、表示する端末と枠は控えから決める（つなぎ直しの途中では表示しない）。
  - 裏にある間に窓の中の配置が変わった端末は、表示したときに大きさが1回変わる。そのときに前の画面を消し損ねるかは中のプログラムの作りによる。
  - 「表示」メニューの「ターミナルの表示を検査」で、表示中の端末の入力欄の枠の重なり・罫線の切れ端・画面とシェルの大きさの食い違い・カーソルの位置を調べ（`src/renderer/screencheck.js`）、崩れていれば「表示を作り直す」を出す。「ターミナルの表示を作り直す」は大きさを1桁変え、応答を待ってから今の大きさに戻して描き直させる。WebGL を付け直したときも全体を描き直す。
  - 自己診断は `TERP_SELFTEST_REDRAW=1`。Ink と同じ消し方で入力欄を描く偽のプログラムを2枚動かし、裏の1枚がある間に左の一覧の幅を変え、画面を読み直してつなぎ直す。開き直す前と同じ画面で戻ること・大きさの変更が届かないこと・裏の端末は表示したときの1回だけであることを確かめる。単体テストは `node --test src/replay.test.js`。
- シェルもつなぐ相手も無い状態が 15 秒続いたら、常駐のプロセスは終わる。
- 常駐のプロセスのコードが変わっても、動いているシェルを守るため古いものを使い続け、窓の右下のトーストで知らせる（「今はしない」「入れ替える…」。2026-10-29 利用者の指示で左の一覧の下から移した）。ターミナルをすべて閉じると、次に開いたときに新しい版に切り替わる。
- 「表示」メニューの「常駐のプロセスを入れ替える…」と、古い版の知らせの「入れ替える…」で、ターミナルを手で閉じずに新しい版へ切り替える（2026-10-29 利用者の指示。ターミナルが多く、閉じて開き直すのが手間）。復旧は時間がかかっても正確さを優先する。
  - シェルは常駐のプロセスが持つため、シェルを残したまま入れ替えることはできない。Mac の再起動と同じく、下の控えから開き直す。
  - 手順: 本体が作業場所と前面のプログラムを拾い直して控えの中身を作る（`pty:replace-plan`）→ 右下のトーストで確かめる → 画面がタブと枠の控えを書き切る → 本体が中身を作り直して控えを書く（`pty:replace-host`）→ 常駐のプロセスに `shutdown` を送り、ソケットのファイルが消えるまで待つ → 窓を読み直す。読み直した画面は、新しい版の常駐のプロセスを起動して控えから開き直す。
  - 確かめは、ほかの案内と同じく窓の右下のトーストに出す（2026-10-29 利用者の指示）。開き直す枚数・会話を再開するターミナル・会話の ID が見つからないターミナル・止まって戻らないプログラム（シェル以外で、会話でないもの）を名前付きで出す。失敗もトーストに出す。
  - 前面が claude・codex なのに会話の ID が見つからないターミナルは、「会話を再開せずに入れ替える」を選ぶと、止めて同じ場所でシェルだけ開き直す（2026-10-29 利用者の指示）。確かめた後に見つからないターミナルが増えていたら入れ替えず、新しい中身で確かめ直す。
  - 入れ替えの間は、止めたシェルの終わりを画面へ伝えない（伝えるとタブと枠の控えが崩れる）。控えから開き直し終わる（`pty:restored`）までは、控えを書き直さない。途中の一覧で控えを上書きすると、開き直しが途中で止まったときに残りが失われるため。Mac の再起動の後の開き直しにも効く。
  - 自己診断は `TERP_SELFTEST_REPLACEHOST=1` と一時フォルダの `TERP_CONFIG_DIR`。偽の claude（確認を飛ばす起動・別の設定のフォルダ）・偽の codex・別のワークスペースに移してドラフトから外した端末・`sleep` を動かした端末・claude の名前で写した node（会話の ID が無い）を入れ替える。確かめている間にボタンを出さないこと・トーストの中身・枚数・名前・題名・作業場所・ワークスペース・会話の再開と起動の仕方と設定のフォルダ・ID の無い端末をシェルだけで開き直すこと・枠とタブの並び・シェルが新しいこと・開き直した後の控えを確かめる。
- Mac の再起動などで常駐のプロセスごと消えたときのために、作業場所・名前・題名・ワークスペース・お気に入り・端末の ID・会話のエージェントと ID・確認を飛ばす起動か を `~/.config/terp/sessions.json` に控える（10 秒ごと、ターミナルを閉じたとき、terp を閉じるとき）。次に開いたら、同じ場所で開き直し、claude は `--resume <ID>`、codex は `resume <ID>` で、止める前と同じ起動の仕方で会話を再開する。前の版の控え（`claudeSession`）は `claude --resume <ID>` で再開する。画面の中身と、動いていた途中の処理は戻らない。
  - 会話の ID は `claude agents --json`（会話の pid と ID を出す）と `ps` の親子関係から、どのシェルの下の claude かを結んで拾う。
  - `claude agents` は既定の設定のフォルダ（`~/.claude`）の会話しか出さない。見つからない claude は、プロセスの環境変数の `CLAUDE_CONFIG_DIR` のフォルダの `sessions/<pid>.json` から拾う。pid の使い回しに備え、控えの起動時刻（UTC で書かれる）とプロセスの起動時刻を比べる。設定のフォルダは控えと履歴に残し、再開するときは `env CLAUDE_CONFIG_DIR=<フォルダ>` を付ける（2026-10-29、別のアカウントで動かした claude の ID が取れず入れ替えられなかった）。
  - codex は記録のファイルを開いたままにしないことがある。普段は直近5分に書かれた記録から探す。入れ替えの前だけは、過去30日の記録のうち codex の起動より後に書かれ、同じ作業場所で始まった対話の会話（サブエージェントと `codex exec` とデスクトップ版を除く）を探し、1つに絞れたときだけ使う（2026-10-29、前日の会話を開き直した codex の ID が取れなかった）。
  - シェルが終わったという知らせを受けても控えは書き直さない。常駐のプロセスごと止まるときはシェルが1つずつ終わるため、書き直すと控えが空になった（2026-10-23 自己診断で検出）。
- AI エージェントの会話の履歴を terp 側でも持ち、⌘M の一覧の右の列に出す（2026-10-27 利用者の指示）。
  - 控えを書くとき（10 秒ごとなど）に、claude は上と同じ方法で、codex は通知の返答を読むときと同じ方法（開いている `rollout-<日時>-<UUID>.jsonl`）で会話の ID を拾う。`~/.config/terp/agent-history.json` に、エージェント・会話の ID・作業場所・ワークスペース・題名（端末の題名）・名前・最初と最後に見た時刻を残す。同じ会話は1件にまとめ、新しい順に 200 件まで。会話の中身は読まない。
  - 列には題名（無ければ名前）・エージェント・リポジトリ（作業外ならフォルダ名）・最後に使った時刻を出し、動いている会話には「開いている」を付ける。絞り込みの文字は履歴にも当てる。× で履歴から消す（会話の記録そのものは消さない）。
  - 押すと、動いているターミナルがあればそこへ移る。無ければ同じ作業場所で新しいターミナルを開き、claude は `--resume <ID>`、codex は `resume <ID>` で再開する。実行ファイル・引数・確認を飛ばすかは左下のボタンと同じ。
  - 自己診断は `TERP_SELFTEST_AGENTHISTORY=1`。本物の claude・codex は動かさず、会話を見つけたことにして、再開は偽の実行ファイルで受ける。

## 自己診断

`TERP_SELFTEST=<出力先> npm start` で起動すると、複数のターミナルを開いて、作業場所の引き継ぎ・一覧への反映・未読の印・閉じる・貼り付け・コピーを確かめ、結果（`result.txt`）と画面（`screen.png`）を書き出して終了する。`TERP_SELFTEST_CMD=claude` を付けると、その TUI を起動した画面を撮る。`TERP_SELFTEST_PERSIST=1`・`2`・`3` を同じ `TERP_CONFIG_DIR` で順に付けて3回起動すると、開き直してもシェルが続くことと、常駐のプロセスが消えた後に控えから開き直すことを確かめる。`TERP_SELFTEST_SETTINGS=1` を付けると、設定の画面の各項目の保存と反映を確かめる。`TERP_SELFTEST_FILES=1` を付けると、右の面のファイルの木・ファイルのタブ・作業ごとのタブの切り替えを確かめる。`TERP_SELFTEST_AGENTS=1` を付けると、エージェントの検出と起動のボタンを、偽のエージェントを足して確かめる。`TERP_SELFTEST_GIT=1` を付けると、一時フォルダにプッシュ先の役の空のリポジトリと作業用の複製を作り、「変更」の面の操作を画面のボタンで確かめる。`TERP_SELFTEST_WORK=1` を付けると、一時フォルダに git のリポジトリを作り、作業の追加・作成・振り分け・削除を確かめる。`TERP_SELFTEST_THEME=1` を付けると、設定ファイルを書き換えてテーマ・強調色・透過・誤りの表示を確かめる。このとき `TERP_CONFIG_DIR` に一時フォルダを指定し、利用者の設定を書き換えない。自己診断の窓は手前に出さずに開く（`showInactive`）。利用者が別の窓で打っている文字を奪わないため。

## アプリとして入れる

入れ方は2つある。普段は `link-app` を使う。

| 入れ方 | コマンド | コードを直したとき |
| --- | --- | --- |
| リポジトリを直接読む | `npm run link-app` | terp を開き直すだけで反映される |
| コードを同梱する | `npm run install-app` | もう一度ビルドして入れ替える |

- `link-app` は `/Applications/terp.app/Contents/Resources/app` を、このリポジトリへのリンクにする。Electron は `app.asar` が無ければ `app` フォルダを読む。
- `link-app` で入れた terp は、リポジトリの作業中の状態をそのまま読む。直している途中で開き直すと、途中の状態で動く。
- Electron の版を上げたときと、`package.json` の `build` を変えたときは、`link-app` をもう一度実行する。
- 設定ファイル（`~/.config/terp/config.json`）は、どちらの入れ方でも保存した瞬間に反映される。

`install-app` は `dist/` にビルドし、ad-hoc 署名して `/Applications/terp.app` に置き換える。

- 署名の鍵（Developer ID）が無いため ad-hoc 署名にしている。手元でビルドしたアプリには隔離の属性（quarantine）が付かないため、Finder から起動できる。`spctl` の判定は rejected になるが、起動には影響しない（2026-10-23 確認）。他の Mac に配る場合は公証が要る。
- node-pty の `spawn-helper` は実行ファイルのため、asar の外（`app.asar.unpacked`）に出している。
- Finder から起動したアプリの PATH は `/usr/bin:/bin:/usr/sbin:/sbin` だけになる。本体から呼ぶコマンド（`lsof`）は絶対パスで書く。シェルの PATH はログインシェルが整える。

## アイコン

- 原本は `build/icon.svg`。`npm run make-icon` で `build/icon.png`（1024px）と `build/icon.icns` を作る（Electron で SVG を焼き、`sips` と `iconutil` で組にする）。
- 起動中の色は `src/themeicon.js` で SVG にし、隠した窓で1024pxの PNG に描いて `app.dock.setIcon` に渡す。窓は描くたびに閉じる。同じ5色なら描き直さず、描画中の変更は最後の色だけを使う。`build/icon.icns` とアプリの中身は書き換えない。
- `src/bundleicon.js` は同じ PNG を一時ファイルにし、JXA から `NSWorkspace.setIcon:forFile:options:` を呼ぶ。「情報を見る」で貼る操作と同じ仕組みで、アプリのフォルダに絵を貼る。閉じている間の Dock・Finder・Launchpad もテーマの色になる。`Contents` の中は書き換えない。
- 貼る相手は、パッケージ版の実行ファイルから3つ上の `.app` フォルダとする。`electron .` の開発時には貼らず、`node_modules` 内の Electron.app を変更しない。自己診断では `TERP_BUNDLE_ICON_TARGET` で相手を差し替える。
- 同じ5色の設定変更では貼り直さない。起動時には1回貼る。`themedIcon` を切ると貼った絵を外し、アプリに入っている元のアイコンへ戻す。5色が同じまま設定を切り替える場合も、貼り付けと解除は反映する。JXA の上限は10秒とし、一時ファイルは成功・失敗にかかわらず消す。失敗は無視し、次の設定変更で再試行する。
- Dock は閉じているアプリの絵を覚えていて、アプリのフォルダの絵を変えても古い絵のまま出す（2026-10-29 利用者の画面で確認。`killall Dock` で作り直すと新しい絵になった）。そのため、その起動で絵を貼り直したときだけ、terp が終わった後に Dock を作り直す（`refreshDockAfterExit`。終わるのを最大10秒待つ）。Dock は一瞬消えて出直す。
- 最後に貼った絵（色と外したか）を設定のフォルダの `bundle-icon.json` に控え、同じ絵が貼れたまま（直下の `Icon\r` の有無で見る）なら起動のたびに貼り直さない。貼り直すと Dock の作り直しが要るため。入れ直して `Icon\r` が消えたら貼り直す。
- `codesign --verify` は、アプリのフォルダの直下に署名の外のファイルがあると報告する。手元で作った ad-hoc 署名の terp は起動に影響しない。
- `npm run install-app` で入れ直すと貼った絵は消える。次に起動したときに貼り直す。
- 自己診断は `TERP_SELFTEST_THEMEICON=1` と一時フォルダの `TERP_CONFIG_DIR` を指定する。本体の最初の描画より前に、一時フォルダ内の空の `Fake.app` を作って相手に指定する。起動時・強調色の変更・無効と再有効・同じ色での描画と貼り付け回数を確かめる。貼ると直下に `Icon\r` ができ、外すと消えることも検査し、出力先に `theme-icon-*.png` を残す。
