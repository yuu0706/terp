# terp の設計方針

terp は、ターミナルを複数開いて素早く切り替えるための macOS 用アプリである。2026-10-23 から、Orca に代わる並列のエージェント開発の道具を目指す（ブランチ `feature/orca-replacement`）。

## 目的

次の 3 つを柱とする。

1. ターミナルの切り替えが速い。
2. テーマなどを設定で変えられる（拡張性）。
3. 新しいターミナルを手軽に開ける。

前提として、表示と操作を通常のターミナルにできるだけ近づける。`claude`・`codex` などの CLI が通常のターミナルと同じように動くことを必須とする。

## 構成

| 層 | 採用 | 理由 |
| --- | --- | --- |
| アプリ | Electron | VS Code・Orca と同じ構成で、`claude`・`codex` との互換性の実績が多い |
| 端末の描画 | xterm.js（WebGL 描画） | VS Code の端末と同じ部品。テーマを JSON と CSS で変えられる |
| 疑似端末 | node-pty | 同上。N-API の配布物があり、Electron 用の再ビルドが不要 |

採らなかった案と理由:

- Tauri: macOS の WKWebView で xterm.js の描画に癖があり、端末の入出力の中継を Rust で書く必要がある。
- Swift + SwiftTerm: テーマや拡張を足すたびに Swift の実装が要り、拡張性の柱に合わない。
- libghostty の組み込み: 組み込み用の API が安定していない。

メモリの使用量は Ghostty より多くなる。これは受け入れる。

## 通常のターミナルに近づけるための決めごと

- シェルはログインシェル（`$SHELL -l`）で起動する。Finder から起動したアプリは PATH を引き継がないため。
- 環境変数: `TERM=xterm-256color`、`COLORTERM=truecolor`、`TERM_PROGRAM=terp`。`LANG` が UTF-8 でなければ `ja_JP.UTF-8` にする。
- 起動元の環境変数（`ELECTRON_*`・`npm_*`・`CLAUDECODE`・`CLAUDE_CODE_*`・`NODE_OPTIONS`）はシェルへ渡さない。
- 文字幅は Unicode 11 の規則に従う（Unicode11 アドオン）。
- キー: ⌘ の付くキーはアプリが受け取り、それ以外はすべてシェルへ送る。Option は Meta として扱う。Shift+Enter は ESC + CR を送る（`claude` の改行。VS Code の `/terminal-setup` と同じ）。
- URL はクリックで既定のブラウザで開く。

## 切り替え（柱 1）

- 開いたターミナルはすべて生かしたまま、表示だけを差し替える。
- Chromium の WebGL は同時に 16 個前後しか持てないため、WebGL 描画は表示中のターミナルにだけ付け、裏に回したら外す。
- 操作: 左の一覧、`⌘1`〜`⌘9`、`⌃Tab`（直前のターミナル）、`⌘⇧[`・`⌘⇧]`（一覧の前後）、`⌘W`（閉じる）。`⌘P`（名前と作業場所のあいまい検索）は未実装。
- 一覧の各行に、名前、動いているプログラム名と作業場所、状態の印を出す。
- 名前の優先順: ダブルクリックで付けた名前 > claude などが端末のタイトルに出した題名 > 作業場所のフォルダ名。
  - claude は会話の題名を自分で作り、タイトル（OSC 0/2）に出す（2026-10-23 実測。例 `◐ Python フィボナッチ数列の生成`）。先頭の記号は、回転（◐◑ など）が作業中、`✳` が入力待ちを表す。
  - 題名は、前面のプログラムがシェル以外のときだけ名前に使う。`Claude Code` などの既定のタイトルは使わない。
  - 記号が回転から `✳` に変わったとき、そのターミナルを見ていなければ通知の印（黄）を付ける。
  - codex のタイトルの出し方は未確認。
- 状態の印: 出力中（緑）・裏で出力があった（青）・通知あり（黄）。通知は OSC 9 / 777 とベルで受け取る。
- 作業場所と動いているプログラム名は、本体が 1.5 秒ごとに `lsof` を1回呼んでまとめて拾う。
- ⌘ の付くキーはアプリのメニューで受ける。`⌃Tab` は端末が先に受け取るため、画面側で処理する。

## 拡張性（柱 2）

設定は `~/.config/terp/config.json` に置く。保存すると、開いている端末にすぐ反映する（フォルダを `fs.watch` で見る）。メニューの「設定ファイルを開く」（`⌘,`）で開ける。

| 項目 | 既定 | 内容 |
| --- | --- | --- |
| `theme` | `null`（Catppuccin Mocha 相当の内蔵の色） | テーマの名前。Ghostty のテーマの書式のファイルを、`~/.config/terp/themes`・`~/.config/ghostty/themes`・Ghostty.app 付属のテーマの順に探す |
| `accent` | `null`（テーマのカーソルの色） | 強調色。新規ボタン・未読の印などに使う |
| `fontFamily` | `"JetBrains Mono", Menlo, "Hiragino Sans", monospace` | フォント |
| `fontSize` | `14` | 文字の大きさ |
| `backgroundOpacity` | `1` | 背景の不透明度（0.2〜1）。Ghostty の `background-opacity` に当たる |
| `backgroundBlur` | `false` | 窓の後ろのぼかし。`true`（半径 20）か半径の数値。Ghostty の `background-blur` に当たる |

- 左の一覧などアプリの枠の色は、テーマの背景色と文字色を混ぜて作る。テーマを変えるだけで枠も揃う。
- JSON の誤りと、見つからないテーマ名は、一覧の下に警告として出し、直すまで消さない。読めない間は既定の値で動く。
- 透過のため、ウィンドウは常に `transparent: true` で作る（作成時にしか指定できない）。背景は一覧と端末の面にだけ塗り、xterm.js 側の背景は透明にする。両方に塗ると、透過のときに重なって濃くなる。
- xterm.css は `.xterm-viewport` を `#000` で塗るため、透明に上書きしている。
- ぼかしは Electron の vibrancy を使わない。vibrancy は窓の裏にすりガラスの板を敷く仕組みで、暗いテーマでは板がほぼ不透明に見え、透過が効かなくなった（2026-10-23 に利用者の目で確認）。Ghostty と同じく macOS の非公開の関数 `CGSSetWindowBackgroundBlurRadius` を koffi で呼ぶ（`src/blur.js`）。macOS の更新で関数が消えたら、ぼかしだけが無くなり透過は残る。
- Ghostty の設定（`~/.config/ghostty/config`）からのフォント・余白・透過の取り込み、キー割り当ての設定、プラグインは未実装。

## 設定の画面

`⌘,` で窓いっぱいに開く（2026-10-23 利用者の指示）。左にメニュー、右に選んだ項目の設定を出す。Esc か × で閉じる。設定ファイルを直接開くのは、メニューの「設定ファイルを開く」に移した。

- 雛形: `src/renderer/settings.js` の `SECTIONS` に、メニューの項目と設定の項目（種類・設定ファイルの名前・説明）を書くと画面が組み上がる。種類は theme・select・text・number・range・toggle・color・action（`FIELD_TYPES`）。設定の名前は `config.js` の `DEFAULT_CONFIG` と同じにする（知らない名前は書き込みで拒否する）。
- 保存は変えたらすぐ行い、保存のボタンは置かない（文字の欄は入力が止まって 800ms 後と、欄から離れたとき）。書いた後は設定ファイルの監視を通して画面に反映する。
- 書き込みは `config.json` を読んで、変えた値だけを差し替えて書く。画面に無い値や手で書いた値は残す。`null` は「書かない（既定に戻す）」として消す。JSON が壊れているときは書かずに、直すよう知らせる。
- 範囲の外の数は書かずに知らせる。一覧に無い値（手で書いたテーマの名前など）も、消さずに「見つかりません」と付けて出す。
- 最初の項目: 外観（テーマ・強調色・フォント・文字の大きさ・背景の不透明度・ぼかし）、AI エージェント（確認なしで起動・メインのエージェント・登録一覧）、詳しい設定（設定ファイルを開く）。
- テーマは名前で絞り込む一覧にし、使用中の印を付けて最初にその位置を表示する。マウスを載せる操作と上下矢印はプレビューだけを変え、クリックと Enter で保存する。選択前に色を比べられないプルダウンは使わない。
- プレビューはターミナルの出力・選択とカーソル・16色・左の一覧・強調色のボタンを表示する。`config.getThemeColors` が実際の適用と同じ色変換を使い、IPC で画面へ返す。強調色の指定があれば優先し、無ければカーソルの色を使う。画面は名前と強調色ごとに結果を再利用し、プレビューの要素だけに色を指定する。幅が足りなければ一覧とプレビューを縦に並べる。
- 見出しの「AI で好みを作成」で、明るさ・好きな色や雰囲気・くっきり具合を質問する。`src/themegen.js` はログインシェルの PATH から claude を探し、設定フォルダで `-p <頼む文> --output-format json --model haiku --tools ""` を実行する。1回60秒で打ち切り、新しい API キーは持たない。作成中も閉じられ、閉じた後の結果は破棄する。
- CLI の JSON の `result` からテーマの JSON を取り出し、名前・6つの色・16色の配列を検証する。文字と背景の WCAG コントラスト比が4.5未満なら1回だけ作り直し、それでも不足すれば理由と再試行を表示する。成功時は同じプレビューと「適用」「作り直す」「やめる」を表示する。
- AI が作ったテーマは「適用」のときだけ `themes/<名前>` に Ghostty の書式で保存する。同名は ` 2`・` 3` を付け、別名のファイルへ書いてから置き換える。`save('theme', 名前)` が設定を更新する。
- `TERP_SELFTEST_THEMEAI=1` は一時フォルダの `TERP_CONFIG_DIR` を指定して使う。出力先の偽の claude を `TERP_CLAUDE_BIN` で渡し、絞り込み・プレビュー・適用・AI の質問・保存・重複名・コントラスト不足の再生成を確かめる。今回の検証は構文検査と偽の CLI による本体の検査であり、Electron の画面の自己診断は未実施である。

- AI エージェントの登録一覧は、未導入・非表示のものも含めて表示する。行を押すと、表示名・実行ファイルの絶対パス・起動引数・確認を飛ばす引数・環境変数を編集できる。文字の欄は 800ms 後とフォーカスを離したときに保存し、編集内容を残して保存の失敗を表示する。
- 行の「表示する」と上下ボタンは `agents` の非表示設定と配列順を更新する。既知のものは「既定に戻す」で上書きを除去し、追加したものは確認ダイアログの後で削除する。「メインにする」は `mainAgent` を更新する（`src/renderer/settings.js`）。
- 登録一覧の初回表示と「確かめ直す」のときだけ `agents:status` を呼ぶ。結果は設定画面を閉じるまで再利用する。`src/agentstatus.js` は `loginEnv()` の環境と `CONFIG_DIR` で `--version`、Claude の `auth status`、Codex の `login status` を実行し、それぞれ 5 秒で打ち切る。エージェントに設定した環境変数は、状態確認には付けない。
- 版は出力の最初の行だけを表示する。ログインは済み・未・確かめられない・確かめる方法が無いのいずれかと、認証方式の語だけを返す。認証の生出力や実行失敗時の出力は IPC へ渡さない。
- `TERP_SELFTEST_AGENTREG=1` は一時フォルダの `TERP_CONFIG_DIR` と組み合わせる。偽の CLI を作り、状態・表示切り替え・引数・環境変数・パス上書き・追加削除・並び替え・メインの指定・アイコン・再確認を検査する。`TERP_AGENT_STATUS_FAKE` は状態確認に使う実行ファイルを指定フォルダで差し替え、見つからなくても本物へ戻さない。Electron の画面を使う検査は今回未実施。

## 新規作成（柱 3）

- 一覧の下端に「新しいターミナル」のボタンを置く。端末の入力欄が画面の下にあるため、視線の移動を減らす（利用者の指示）。
- `⌘T` とボタン: 表示中のターミナルと同じ作業場所で開く。作業場所はシェルのプロセスの cwd を読む。
- `⌘N`: 最近使った作業場所と `~/Documents/git` の下を候補にして、あいまい検索で選んで開く。
- プロファイル: 「この作業場所で `claude` を起動」のような型を設定に書き、キー 1 つで開く。
- 名前は作業場所から自動で付け、ダブルクリックで変えられるようにする。

## 作業（worktree）

Orca の中心の機能に倣い、課題ごとに git の worktree を作り、その中でエージェントを動かす。利用者が Orca で使っていて terp に求めた機能は、作業ごとの worktree・変更の差分の確認・ファイルの編集・PR の作成の4つ（2026-10-23 聞き取り）。最初に作業ごとの worktree を作った。

- 左の一覧は「リポジトリ > 作業 > ターミナル」の3段にする。どの作業にも入らないターミナルは「その他のターミナル」に出す。
- terp が記録するのは、一覧に出すリポジトリだけ（`~/.config/terp/projects.json`）。worktree の一覧・ブランチ・変更の数は、毎回 git から読む（5 秒ごとと、ウィンドウに戻ったとき）。Orca やコマンドで作った worktree もそのまま出る。
- ターミナルの所属は、作業場所（cwd）を含む worktree のうち、いちばん深いもので決める。所属を記録しないため、`cd` で別の作業へ移れば一覧の場所も移る。
- 新しい作業は `<リポジトリ>.worktrees/<ブランチ名の / を - にしたもの>` に作る。手元の worktree の置き方はリポジトリごとにばらばらだった（横並び・`.worktrees/`・`-worktrees/`）ため、新しく作るものだけ揃える。
- 同じ名前のブランチが既にあれば、それを使う。無ければ「元にするブランチ」（既定は `origin/HEAD` の先、無ければ本体の今のブランチ）から作る。作ったら、選んだコマンド（`claude`・`codex`・なし）をターミナルで起動する。
- 作業の削除は `git worktree remove` だけで行い、`--force` は付けない。変更のあるファイルが残っている作業は、削除のボタンを押せなくし、理由を出す。ブランチは消さない。消す前に、その作業のターミナルを閉じる。
- 「一覧から外す」は `projects.json` から消すだけで、ファイルには触れない。
- リポジトリの並びは `projects.json` の順で、見出しの行をドラッグ＆ドロップするか、見出しを選んで ⌥↑ / ⌥↓ で変える（2026-10-23 利用者の指示）。つかんでいる間と記録を書いている間は、5 秒ごとの読み直しを止める（読み直すと古い順に戻って見えるため）。

## 画面の配置（Orca に合わせる）

2026-10-23、利用者の指示「Orca と同じ配置にする」に従い、Orca の設定ファイル（`orca-data.json` の `ui`・`workspaceSession`）から読み取った配置に寄せた。

| 場所 | Orca | terp |
| --- | --- | --- |
| 左 | リポジトリごとの作業（worktree）の一覧 | リポジトリ > 作業。作業の下のターミナルの行は、Orca の作業のカードの中のエージェントの一覧に当たる |
| 上 | 選んでいる作業のタブ。ターミナルとファイルが同じ並びに混ざる（`tabsByWorktree`・`unifiedTabs`） | 同じ。作業に入らないタブは「その他」として1つのまとまりにする |
| 右 | 開け閉めする面。中に切り替えがある（`rightSidebarTab: explorer` など） | 1つの面に「ファイル」と「変更」の切り替え。上の帯のボタン（`⌘⇧E`・`⌘⇧G`）で開け閉めする |

- タブのキーは、ターミナルが `t:<番号>`、ファイルが `f:<パス>`。開いた順に並べ、ファイルは表示中のタブの隣に開く。
- 上のタブには、表示中のタブと同じ作業のものだけを出す。左の作業の行を押すと、その作業の最近見たタブへ移る（無ければターミナルを開く）。
- `⌘1`〜`⌘9`・`⌘⇧[`・`⌘⇧]` は上のタブの順に従う。左の一覧の `⌘` の番号も、上のタブに出ているものにだけ付ける。`⌘W` は表示中のタブを閉じる。
- 新しいターミナルとエージェントは、表示中のタブの場所で開く（ファイルのタブならそのフォルダ）。

### 作業画面の分割

2026-10-24 追加。上の帯の下を最大6枠に分け、ターミナル・ファイル・サブエージェントの記録を同時に表示する。

- `panes.js` の木は、葉を `{ type: 'pane', id, key }`、分割を `{ type: 'split', dir, children, sizes }` とする。`dir` は左右が `row`、上下が `column`。`sizes` の合計は1とする。操作関数は DOM に依存しない。
- 操作中の枠は1つとし、`activeKey` はその枠のタブを表す。タブの中身は既存の要素を枠へ移し、未表示の要素は帯の下の木の外にある置き場で隠す。要素を作り直す方式は、シェル・編集内容・スクロール位置を失うため採用しない。
- タブを押すと、表示済みならその枠へ移り、未表示なら操作中の枠を入れ替える。分割中だけ操作中の枠を強調色の線で囲む。枠の右上の × は枠だけを閉じる。
- 上のタブ、左の端末と押せるサブエージェントの行、右のファイルの行を `text/x-terp-tab` でドラッグする。リポジトリの並べ替えの `text/x-terp-project` と区別する。未表示のファイルと記録はドロップ時に開く。
- 枠の端25%は、その側へ半分ずつ分割する。角では近い端を選ぶ。中央へのドロップと6枠でのドロップは中身を入れ替える。同じタブは重複させず、移動元の枠は畳む。
- 境目は約5pxとし、ポインタを捕まえて隣り合う割合を変える。各枠の最小寸法は120pxとし、入れ子の分割の最小寸法も合算する。窓が狭ければ作業画面内でスクロールする。ダブルクリックで隣り合う割合を半分ずつに戻す。
- 表示中の端末すべてに WebGL を付け、未表示の端末から外す。サイズ変更は FitAddon と既存の ResizeObserver で反映し、Monaco は既存の自動レイアウトを使う。
- タブを閉じた枠は、同じ作業の最近見た未表示タブで埋める。無ければ枠を畳み、最後の枠なら「新しいターミナル」の空表示に戻す。
- `⌘\` は同じ場所に新しい端末を開いて右へ分割する。`⌘⌥` と矢印キーは、画面上でその方向に隣接する枠へ移る。
- `tabs.json` の `layout` に枠のキーと割合を残す。復元時は消えたタブ・重複したタブ・サブエージェントの記録を除き、1つの子だけ残った分割を畳む。古い控えに `layout` が無ければ1枠で開く。
- 枠内の操作とドロップ予告は作業画面内の層に閉じ込め、差分表示（`z-index: 2`）・メニュー（10）・設定（20）の下に置く。

自己診断は `TERP_SELFTEST_SPLIT=1` で操作・ドラッグ・サイズ変更・メニューを、`TERP_SELFTEST_PERSIST=1` → `2` → `3` で枠とタブの復元を確かめる。

## ファイルの閲覧と編集

### ドロップによるパスの入力

2026-10-24 追加。Finder のファイル・フォルダと、右のファイル一覧からの `⌥` 付きドロップで、表示中の枠にパスを入力する。

- `document` の `dragover`・`drop` で `Files` の既定の動作を止め、枠の外でもファイルへの画面遷移を防ぐ。内部のタブ移動とリポジトリの並べ替えは従来の種類で扱う。
- 実パスは preload の `webUtils.getPathForFile(file)` から取得する。廃止された `File.path` は使わない。実パスの無い項目は除く。
- ターミナルには空白・タブ・シェルの記号をバックスラッシュで逃がしたパスを入れる。複数は空白で区切り、最後に空白を1つ付ける。Enter は送らない。
- 入力には xterm の `term.paste(text)` を使い、括弧付き貼り付けを反映する。生の文字列を直接 PTY へ書く方式は、claude などで入力が分かれるため採用しない。落とした枠を操作中にして入力の焦点を移す。
- 文字のエディタには素のパスを改行で区切り、Monaco が求めたドロップ位置に挿入する。位置を求められなければカーソル位置を使う。挿入は1回の取り消しで戻せる。
- 画像などの閲覧枠とサブエージェントの記録には入力しない。パスのドラッグ中は分割の予告を出さず、受け取れる枠に強調色の細い線を出す。
- 右のファイルとフォルダの行には `text/x-terp-path` を付ける。`⌥` があればパスを入力する。ファイルの行は従来の `text/x-terp-tab` も持ち、`⌥` が無ければ分割・入れ替えを行う。
- パスのエスケープと入力先の判定は `droppaths.js` に置く。Monaco 独自のドロップ処理より前に受け取り、ファイルを別途開かせない。

自己診断は `TERP_SELFTEST_DROPPATHS=1` で実行する。合成した `File` には実パスが無いため、`window.__terp.dropPaths(paneId, paths)` で入力を確かめる。既定の動作の抑止と内部ドラッグは合成イベントでも確かめる。

### 閲覧と編集の動作

- 端末に出た実在するファイルのパスはクリックでタブに開き、行・桁の指定があればエディタの中央にその行を表示してカーソルを置く。フォルダは Finder で表示する。
- パスのリンクは折り返しをつないで検出する。相対パスは端末の作業場所、次に worktree の一番上から探し、実在確認の結果は5秒間再利用する。
- 右の面の「ファイル」は、表示中のタブの場所を含む worktree の一番上（git の外ならその場所）から木の形で出す。`.git` と `.DS_Store` は出さない。フォルダの中身は開いたときに読み、開いているフォルダだけを 5 秒ごとに読み直す。
- ファイルを押すとタブで開く。文字のファイルは Monaco Editor で編集し、言語は登録された拡張子とファイル名から決める。該当しなければ `plaintext` にする。背景は透明とし、文字・選択・行番号・構文の色とフォントは端末の設定に合わせ、設定の変更時にも反映する。
- Monaco の AMD loader を `app.js` より先に読み、エディタ本体の読み込みは Promise を共有する。作業用ファイルは本体で `min/vs/assets/editor.worker-*.js` を探し、同期 IPC で渡す。CSP は変更しない。
- 2 MB を超える文字のファイルと、先頭 8 KB に NUL を含むファイル（バイナリ）は中身を出さず、既定のアプリで開くボタンを出す。画像は画像として出し、10 MB を超える画像は中身を出さない。
- `⌘S` とメニューの「保存」で表示中のファイルを UTF-8 で保存する。別名に書いてから置き換え、既存のアクセス権を保つ。未保存の変更があるタブは名前の後ろに `●` を付ける。読み込み時・保存時の `mtime` と一致しなければ書き込まず、上書きの確認後に保存する。
- 開いている文字のファイルの `mtime` を2秒ごとに確かめる。未保存の変更が無ければ、カーソルとスクロールの位置をできるだけ保って読み直す。変更があれば「外で変更されました」の帯で、読み直すか、このまま編集するかを選ぶ。「このまま」を選んでも保存時の上書き確認は残る。削除されたファイルは帯で知らせ、タブを残す。
- 「再読み込み」やファイルのタブを閉じる操作では、未保存の変更があれば既存と同じ `<dialog>` の部品で確認する。閉じる場合は保存・破棄・キャンセルを選び、保存に失敗した場合は閉じない。
- 窓を閉じる操作と `⌘Q` は、本体で一度止めて画面に問い合わせる。画面はすぐ応答し、未保存のファイルがあれば全件保存・破棄・キャンセルを選ぶ。2秒以内に画面が応答しなければ閉じる。応答後は利用者の選択を待ち、既存のシェル保持と終了時の控えの保存を続ける。
- 開いたファイルの絶対パス・ターミナルを含むタブの並び・表示中のタブを、設定のフォルダの `tabs.json` に保存する。タブの追加・削除・切り替えから 250 ms 後にまとめて、別名に書いてから置き換える。
- terp を開き直すと、ターミナルの復元後に存在するファイルだけを読み直し、タブの並びと表示中のタブを戻す。文字のファイルは復元後もエディタで開く。右の面の「ファイル」が閉じていても復元する。存在しないタブのキーは捨て、控えに無いタブは後ろに置く。表示していたタブが無ければ、最後に見たターミナルのままにする。復元途中は控えを上書きしない。

## AI エージェントの起動

手元に入っている AI エージェントの CLI を自動で探し、起動のボタンを「新しいターミナル」の上に並べる（2026-10-23 利用者の指示）。

- ログインシェルの PATH から探す（`src/agents.js`）。ターミナルで打って動くものと揃えるため。探すのは、よく使われるもの（claude・codex・gemini・opencode・cursor-agent・copilot・aider・amp・qwen・goose・crush・droid）と、設定ファイルの `agents` に書いたもの。
- `agents` の各項目は `{ command, label, args, bypassArgs, path, env, hidden }`。同じ `command` の既定には書いた値だけを重ね、未知のコマンドは追加する。設定の配列順を優先し、未指定の既定はその後ろに並べる。`path` があれば PATH を探さず、絶対パスで存在と実行権限を確かめる。検出結果には導入の有無・場所・既定値・アイコンも含む（`src/agents.js`）。
- 未導入か `hidden: true` のものは、左下のボタン・プルダウン・メイン・新しい作業の選択肢に出さない。設定の監視から `applyConfig` と `refreshAgents` を通して起動用の一覧を更新する。
- `env` の名前は `[A-Za-z_][A-Za-z0-9_]*` のみを使う。起動の 1 行を `env 名前='値' … '実行ファイル' 引数` とし、値と実行ファイルの単一引用符を逃がす。環境変数は起動時だけ付ける（`src/renderer/app.js` の `agentCommandLine`）。
- アイコンは `src/renderer/icons/agents/` のローカル SVG を使う。色付きは画像、`currentColor` のものは CSS mask で文字色に合わせる。既知の定義に表示方式を持ち、アイコンの無いものは既存のロボットを表示する。CSP は変更しない。
- ボタンを押すと、表示中のターミナルと同じ作業場所で新しいターミナルを開き、そのコマンドを打つ。空白を含む絶対パスは引用符で囲む。
- 「新しい作業」の画面の「作ったら起動する」も、見つかったエージェントと「起動しない」から選ぶ。
- エージェントを入れたり消したりしたら、ウィンドウに戻ったときに探し直す。
- タブの並びのすぐ右に、＋（新しいタブのプルダウン）とメインのエージェントのボタンを置く（2026-10-23 利用者の指示）。プルダウンには「ターミナル」と見つかったエージェント全部を出す。メインは設定の `mainAgent`（無ければ見つかった最初のもの）で、押すとプルダウンなしで起動する。どちらも ⌥ で確認あり・なしが逆になる。
- 確認を飛ばす起動（2026-10-23 利用者の提案）: ファイルの読み書きやコマンドの実行の確認を出さずに起動する引数（`bypassArgs`）をエージェントごとに持つ。値は Orca の `agentDefaultArgs` と同じ（claude は `--dangerously-skip-permissions`、codex は `--dangerously-bypass-approvals-and-sandbox` など。2026-10-23 に利用者の Orca の設定で確認）。
  - 利用者は「ディレクトリへのアクセスを許可せずに起動する」機能と捉えていたが、実際は逆で、確認を飛ばし、codex はサンドボックスも外す。この点を伝えたうえで、普段は確認なしで起動すると決めた。
  - 設定の `skipApprovals` が true なら、ボタンは確認なしで起動する。⌥ を押しながら押すと逆になる。コードの既定は false（確認あり）にし、利用者の設定ファイルにだけ true を書いた。公開しているリポジトリのため、入れただけで確認なしで動くことを避ける。
  - 確認なしで起動したターミナルには、一覧の行に「確認なし」の印を付ける。開き直しても残るよう、常駐のプロセスに預ける。

## サブエージェントの動き

左の一覧では、ターミナルのすぐ下に、そのシェルの下で動くサブエージェントを出す。
利用者は説明・最後の操作・経過時間を確認し、Claude の行から記録をタブで開ける。
左の「作業」の見出しには設定のボタンも置き、`⌘,` と同じ設定の画面を開く。

- `src/subagents.js` は `snapshot.claudeSessions(shellPids)` を使い、シェルと Claude の会話を結ぶ。`~/.claude` と `~/.claude2` の `projects` 直下を調べ、会話の ID に一致するフォルダの `subagents` を読む。作業場所からフォルダ名を推測しない。
- 状態は `meta.json` の `finished` で決める。記録の更新が10分以上止まったものも終了扱いにする。終了したものは会話ごとに新しい20件まで残し、画面では「終わったもの n 件」に畳む。開閉状態はターミナルごとに保持する。
- 開始時刻は記録の先頭64 KB、最後の操作は末尾256 KBから拾う。大きな通信記録の全体を、一覧を更新するたびに読まないためである。`user` と `assistant` 以外の行と、`thinking` の内容は表示しない。
- `codex exec` はシェルの子孫のプロセスから拾い、`-C` の場所の名前を説明にする。プロセスが消えると一覧から外す。記録のファイルが無いため、行からタブは開かない。
- 一覧は3秒ごとに読み、内容が同じなら描き直さない。記録のタブは最初に末尾1 MBを読み、動いている間は2秒ごとにバイト位置から続きを足す。書きかけの行は次の読み込みに残す。下端を見ている場合だけ追従する。
- 記録のタブのキーは `s:<記録の絶対パス>` とし、表示中のタブの隣に開く。所属する作業は親ターミナルの作業場所から決める。`tabs.json` の控えには含めない。
- 記録は読み取りだけとし、HTMLとして解釈しない。IPCは既存の `safe` を使い、`{ ok, value, error }` の形で成功と失敗を返す。既存のCSPを維持し、外部のスクリプトや画像は読み込まない。

`TERP_CLAUDE_DIRS`（`:` 区切り）で探索する設定フォルダを差し替えられる。
`TERP_FAKE_CLAUDE_SESSION` は自己診断時だけ有効とし、全シェルを指定した会話に結ぶ。
`TERP_SELFTEST_SUBAGENTS=1` は出力先に偽の設定フォルダを2つ作り、稼働中1件と終了2件で一覧・開閉・追記・タブ・設定ボタンを確かめる。
今回の実装では、構文検査と偽の記録を使った本体の検査を行う。Electron の画面を使う自己診断は未実施である。

## git の管理

右の「変更」の面（上の帯の「変更」のボタン、`⌘⇧G`）で、表示中のターミナルの作業場所を含む worktree の git を扱う（2026-10-23 利用者の指示）。

- できること: ブランチと上流との差（↑↓）の表示、変更のあるファイルの一覧（競合・ステージ済み・未ステージ。追跡外を含む）、差分の表示、ステージとステージの取り消し（1件・すべて）、コミット、プッシュ、プル、フェッチ。
- 認証は terp で持たない。ターミナルで git を打ったときと同じもの（SSH の鍵・キーチェーン・gh の認証・`includeIf` による名義の切り替え）をそのまま使う（利用者の指示「端末内の認証情報を使う」）。
  - Finder から起動したアプリは PATH が細く、SSH エージェントや gh が見つからないことがある。ログインシェル（`$SHELL -i -l -c 'env -0'`）の環境を一度だけ読み、git に渡す。読めなければ PATH だけ足す。
  - 認証の入力を求められると止まるため、`GIT_TERMINAL_PROMPT=0` にする。入力が要る認証は失敗として面に出す。
- コミットする名義（`user.name`・`user.email`）を面に出す。業務と個人のアカウントを使い分けているため、どちらの名義でコミットするかを確かめられるようにする。
- コミットのボタンは、ステージ済みのファイルが無い・競合がある・メッセージが無いときに押せなくし、理由を出す。フック（pre-commit など）はターミナルと同じく走る。
- プッシュは、追跡先の無いブランチなら `--set-upstream origin HEAD` で作る。プルは `--ff-only` で、履歴が分かれていたら失敗として返す（自動でマージしない）。
- 変更を捨てる操作（`restore`・`reset --hard`・`clean` など）は持たない。取り返しがつかないため、ターミナルで行う。
- 差分は 5,000 行で打ち切る。バイナリのファイルは差分を出さない。

### 履歴の閲覧

2026-10-24 に実装。本体は一時リポジトリで検証済み。Electron の自己診断と実画面での確認は未実施。

右の面の「履歴」（上の帯の時計のボタン、`⌘⇧H`）で、表示中のタブの場所を含む worktree の履歴を表示する。
「ファイル」「変更」「履歴」の開閉と選択は `app.js` の `setPanel` に集め、同時に1つだけ表示する。
既存の右の面の幅と重なり順を使い、枠を狭めた場合も一覧と詳細をそれぞれの領域内でスクロールする。

- `src/history.js` はログインシェルの環境で git を呼び、`history:log`・`history:commit`・`history:diff` の IPC で結果を渡す。失敗は既存の `safe` で返す。
- 一覧は `git log --graph` の線とコミットを分け、線だけの行も表示する。100件ずつ読み、現在のブランチと全ブランチを切り替えられる。上流との差に含まれるコミットは「↑」で示す。
- 絞り込みは入力終了から300ミリ秒後に行う。16進の4〜40字はコミットを直接指定し、それ以外は件名と作者を OR で検索する。`--grep` と `--author` の集合を合わせ、件名の一致を確認して元のグラフの順に返す。
- ファイルの見出しの「履歴」で、そのパスを変更したコミットだけを表示する。見出しの「×」で解除する。`--graph` と併用できないため `--follow` は付けない。
- 面を開いている間は10秒ごとに読み直し、読み込み済み件数と表示位置を保つ。worktree が変わったら先頭から読み、ファイルの絞り込みを解除する。読み込み中の結果は要求の番号で区別し、古い結果で新しい条件を上書きしない。
- コミットの詳細は `c:<worktree>@<ハッシュ>` のタブで開く。同じコミットは再利用し、親のコミットへ移動できる。既存の枠へのドラッグと分割に対応するが、開き直し用の控えには含めない。
- 詳細は全文メッセージ、作者・コミッター、日時、親、印、変更ファイルを表示する。マージは最初の親との差、最初のコミットは空のツリーとの差を表示する。名前変更は元と先の両方を差分に渡す。
- ファイルの行を押すと差分を開閉する。差分の表は「変更」の `renderDiff` を共用し、同じ5,000行の上限を使う。バイナリと打ち切りは文字で示す。
- ハッシュは git の呼び出し前に検証する。履歴を書き換える操作は持たない。
- `TERP_SELFTEST_HISTORY=1` の自己診断は、一時リポジトリでページ追加、枝・印・未プッシュ、全ブランチ、検索、詳細と差分、親、ファイルの絞り込み、ハッシュの検証を確かめる。

## セッションの保持

terp を閉じても開き直しても、シェルと中のプログラム（claude など）は止めない（2026-10-23 利用者の指示）。`link-app` で入れた terp はコードを直すたびに開き直すため、開き直すたびに会話が切れるのを防ぐ。

- シェルは常駐のプロセス `src/ptyhost.js` が持つ。terp の実行ファイルを `ELECTRON_RUN_AS_NODE=1` で Node として起動し、terp からは切り離す（`detached`）。Orca の `orca-terminal-host` と同じ作り。
- terp とは Unix ソケット（一時フォルダの `terp-<設定のフォルダのハッシュ>.sock`）で、1行1つの JSON をやりとりする。ソケットのパスは 104 バイトまでのため、一時フォルダに短い名前で置く。設定のフォルダごとに分かれるため、自己診断は利用者の常駐のプロセスとつながらない。
- 常駐のプロセスは、各シェルの出力の末尾 2 MB を残す。terp がつなぎ直したら、それを流して画面を作り直し、大きさを一度変えて戻して全画面のプログラムに描き直させる。名前・題名・最後に見た時刻も預かる。
- シェルもつなぐ相手も無い状態が 15 秒続いたら、常駐のプロセスは終わる。
- 常駐のプロセスのコードが変わっても、動いているシェルを守るため古いものを使い続け、画面で知らせる。ターミナルをすべて閉じると、次に開いたときに新しい版に切り替わる。
- Mac の再起動などで常駐のプロセスごと消えたときのために、作業場所・名前・claude の会話の ID を `~/.config/terp/sessions.json` に控える（10 秒ごと、ターミナルを閉じたとき、terp を閉じるとき）。次に開いたら、同じ場所で開き直し、claude は `claude --resume <ID>` で会話を再開する。画面の中身と、動いていた途中の処理は戻らない。
  - 会話の ID は `claude agents --json`（会話の pid と ID を出す）と `ps` の親子関係から、どのシェルの下の claude かを結んで拾う。
  - シェルが終わったという知らせを受けても控えは書き直さない。常駐のプロセスごと止まるときはシェルが1つずつ終わるため、書き直すと控えが空になった（2026-10-23 自己診断で検出）。
- codex の会話の再開は未対応。

## 自己診断

`TERP_SELFTEST=<出力先> npm start` で起動すると、複数のターミナルを開いて、作業場所の引き継ぎ・一覧への反映・未読の印・閉じる・貼り付け・コピーを確かめ、結果（`result.txt`）と画面（`screen.png`）を書き出して終了する。`TERP_SELFTEST_CMD=claude` を付けると、その TUI を起動した画面を撮る。`TERP_SELFTEST_PERSIST=1`・`2`・`3` を同じ `TERP_CONFIG_DIR` で順に付けて3回起動すると、開き直してもシェルが続くことと、常駐のプロセスが消えた後に控えから開き直すことを確かめる。`TERP_SELFTEST_SETTINGS=1` を付けると、設定の画面の各項目の保存と反映を確かめる。`TERP_SELFTEST_FILES=1` を付けると、右の面のファイルの木・ファイルのタブ・作業ごとのタブの切り替えを確かめる。`TERP_SELFTEST_AGENTS=1` を付けると、エージェントの検出と起動のボタンを、偽のエージェントを足して確かめる。`TERP_SELFTEST_GIT=1` を付けると、一時フォルダにプッシュ先の役の空のリポジトリと作業用の複製を作り、「変更」の面の操作を画面のボタンで確かめる。`TERP_SELFTEST_WORK=1` を付けると、一時フォルダに git のリポジトリを作り、作業の追加・作成・振り分け・削除を確かめる。`TERP_SELFTEST_THEME=1` を付けると、設定ファイルを書き換えてテーマ・強調色・透過・誤りの表示を確かめる。このとき `TERP_CONFIG_DIR` に一時フォルダを指定し、利用者の設定を書き換えない。自己診断の窓は手前に出さずに開く（`showInactive`）。利用者が別の窓で打っている文字を奪わないため。

## アプリとして入れる

入れ方は2つある。普段は `link-app` を使う。

| 入れ方 | コマンド | コードを直したとき |
| --- | --- | --- |
| リポジトリを直接読む | `npm run link-app` | terp を開き直すだけで反映される |
| コードを同梱する | `npm run install-app` | もう一度ビルドして入れ替える |

- `link-app` は `/Applications/terp.app/Contents/Resources/app` を、このリポジトリへのリンクにする。Electron は `app.asar` が無ければ `app` フォルダを読む。
- `link-app` で入れた terp は、リポジトリの作業中の状態をそのまま読む。直している途中で開き直すと、途中の状態で動く。
- Electron の版を上げたときと、`package.json` の `build` を変えたときは、`link-app` をもう一度実行する。
- 設定ファイル（`~/.config/terp/config.json`）は、どちらの入れ方でも保存した瞬間に反映される。

`install-app` は `dist/` にビルドし、ad-hoc 署名して `/Applications/terp.app` に置き換える。

- 署名の鍵（Developer ID）が無いため ad-hoc 署名にしている。手元でビルドしたアプリには隔離の属性（quarantine）が付かないため、Finder から起動できる。`spctl` の判定は rejected になるが、起動には影響しない（2026-10-23 確認）。他の Mac に配る場合は公証が要る。
- node-pty の `spawn-helper` は実行ファイルのため、asar の外（`app.asar.unpacked`）に出している。
- Finder から起動したアプリの PATH は `/usr/bin:/bin:/usr/sbin:/sbin` だけになる。本体から呼ぶコマンド（`lsof`）は絶対パスで書く。シェルの PATH はログインシェルが整える。

## アイコン

- 原本は `build/icon.svg`。`npm run make-icon` で `build/icon.png`（1024px）と `build/icon.icns` を作る（Electron で SVG を焼き、`sips` と `iconutil` で組にする）。
- アイコンを変えたら、`npm run link-app` で入れ直す。Dock や Finder に古い絵が残るときは、terp を開き直す。
